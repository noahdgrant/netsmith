# Design a board with netsmith

This skill assumes only the `netsmith` command and the project. Entry point: the project's `AGENTS.md`. The language guide (`docs/netsmith/LANGUAGE.md`; `docs/LANGUAGE.md` in netsmith's own repository) defines the syntax. Read its quick start and the sections you use.

## Steps

1. Write the requirements as numbers before any code: supply voltage with tolerance, each load's current range, connectors, number of layers, the factory. Ask the user for what is missing. Do not guess a voltage or a current.
2. Start the project: `netsmith init` in an empty directory. It writes `netsmith.toml`, `src/main.nsm` (a working LED board), `.gitignore`, `README.md`, `AGENTS.md`, these skills and the guide. In an existing project, skip this.
3. Replace `src/main.nsm` with a board that states the requirements. Say what each part must achieve, as ranges. Do not name part numbers. The solver picks real parts from its catalogs. Only when the user names a part (a bill of materials to match, a part they have) hold it to that row with a hand pick in the source, `.c1: Capacitor { .capacitance &= 10uF +/- 10%; .lcsc &= "C307331" }` (or `.mpn &= "..."`): it comes before the pick lock, and the solver still checks the row against the design. There is no picks file.
4. Give the board a process (`.process: TwoLayer { .stackup.thickness &= 1.6mm }`) and name the nets on the board, never in a module.
5. Say what the board looks like only if the requirements do. The circuit source keeps the ground pours on the outer layers (`.process.top.net &= "GND"`). The size and corners (`.outline: Outline`), cutouts, areas where copper or parts are forbidden (`Keepout`), mounting holes, fiducials, a `Label` and every requirement on where a part goes are **physical intent**: they go in the board's physical file `src/<stem>.physical.nsm`, as `physical for Board { case { ... } }` (ADR 0048), never in the board; a board that states one is an error that says where it goes. Use `netsmith-use-constraints`. Ask the user for the numbers: do not guess a size. If the user has the enclosure as a DXF, take the outline, cutouts and mounting holes from it instead of typing them: `netsmith dxf import case.dxf --layer EDGE --holes-layer HOLES` (with no `--layer` it lists the layers and their entity counts when it cannot tell; ask the user which is the board edge) prints the text for the `case` section, and `--write src/board.nsm` puts it in the physical file (made if it is not there; comments stay) with a diff. It refuses an outline that is not a rectangle with equal rounded corners (no polygon outline yet) and a file with no units (`--units`); tell the user, do not approximate. Where a part ends up is not written in either: that goes in `<stem>.pcb.toml` beside them, which an editor or a placer writes. `docs/LANGUAGE.md` has the sections "The physical file" and "The shape of a board".
   Give each load rail its worst-case current (`.current &= 0A..2A`): netsmith draws every net at the width IPC-2221 needs for the sum of the currents it works out on it (Kirchhoff's current law, every load on at once, so a shared ground carries all the returns; ADR 0036), including nets no rail touches, so do not state `.min_track` for current. Read each `note: the current of ... is not known` it prints: state the current of one of the things it names, since a net with two or more unknown currents is not sized and stays at the process's least. A `warning: ... IPC-2221 guideline` appears only for a `.min_track` you stated that is too narrow: widen it, or state a higher `.process.max_temperature_rise` (10 K unless stated) and tell the user you did. Ask whether the project wants these to stop the build (`guidelines = "error"` in `netsmith.toml`, or `--strict` for one run).
6. Run `netsmith build`. Read the first error only, fix it, and run again. Use `netsmith-read-errors` for the messages.
7. Run `netsmith editor` and look at the schematic, the power tree and the bill of materials. Check that each pin is on the net you meant and that no rail is asked for more than its supply can give.
8. Run `netsmith fab`. It places and routes the board, runs the design rules check, and writes `fab/`. If the project has several boards and the user wants some of them, or several copies, write an order in `netsmith.toml` (`[order.<name>.boards]`, a board or a system as its folder is named, and its quantity) and run `netsmith fab --order <name>`. Continue with `netsmith-prepare-fab-order`.
9. Check the board's heights as numbers and look at it, before you tell the user it is done (no KiCad, nothing written but the picture): `netsmith board3d <file.nsm> --json` gives each part's `z_top`, where the height came from (`unknown` is `null`: ask for the number) and each height limit's margin; `netsmith render <file.nsm> --view iso --out board.png` draws the board in 3D, and you read the PNG with your image viewer (`--view top` or `bottom` for a face, `--highlight J1` or `--highlight limit:lid` to light up a part or a limit, `--section x=12.5` to cut it, `--xray`; `docs/BOARD3D.md`, "Pictures for agents"). A part drawn as a flat orange outline has no known height; say so. When the user has `netsmith editor` open on the project, drive the page they are looking at instead of drawing your own: `netsmith view --view top --highlight J1 --picture j1.png` lights J1 in their 3D view, looks from the top and saves what the page shows, so the user and you see the same thing (the same flags as `render`, plus `--select`, `--colour-by margin`, `--height-preview <mm>` and `--layers-apart`; `netsmith view` alone prints what the page shows now, `--json` for every field). It needs a page open (`no editor page is open; open http://127.0.0.1:<port>` says where; start `netsmith editor` first if it says nothing is listening) and exits 2 with the reason for an id the board does not have; it changes no file and never the design.

## Boards that plug into each other

When the design is several boards (a carrier with sockets, plug-in cards with matching headers), each board is its own `board` with its own nets and a `system` places them (guide: "Systems and ports", "Connectors that mate"). Do not join ports with `~` where a connector carries them: mate the connectors (`.carrier.slot.mating ~ .card.j1.mating`), contact N to contact N, and the checker derives the join of the rails and buses that the contacts carry and refuses a second `~` for them.

1. Give each board its connector and wire it to its own ports and parts by pin (`.supply.pos ~ .j1.p2`). A header goes with a socket; both need the same positions, rows and pitch. Ask the user which contact is which: do not guess a pinout.
2. Every mate that carries power or a signal needs at least one ground contact, and enough of them: a contact is rated from its catalog row (3 A for the standard single-row 2.54 mm parts), and the supply and the ground each need `current / rating` contacts. A connector the library has no rating for is not checked, and `netsmith build` lists the check as not evaluated: tell the user.
3. A pinout that is the same turned end for end gets a `mating guideline` warning: key the connector (`.mating.keyed &= "polarised"` on a part that is) or change the pinout, and tell the user which.
4. Read the System view in `netsmith editor`: each mate with its contacts coloured by role, and the ground groups (which boards share a ground).

## Rules

- State what the circuit needs, not what you hope the part is: `.effective_capacitance >= 4.7uF`, not a marked value.
- Put reusable circuits in `src/*.nsm` as modules (`netsmith-write-a-module`).
- A board that has no `process` builds only as a schematic.
- The standard catalogs hold only the verified JLCPCB parts. If a catalog has nothing for a value, change the requirement or the circuit, and tell the user which. A part the user wants and the catalogs lack goes in the project's own catalog file (`catalogs/<catalog>.csv`: every `*.csv` in `catalogs/` is a catalog, no line in `netsmith.toml`), with its `source` and only from a record you fetched. Do not invent a part number.
- Who assembles the parts: `assembly = "fab"`, `"hand"`, `"none"` or `"consigned"` under `[project]` in `netsmith.toml` is the default for every part nothing else speaks for (a part's own `.assembly &=` wins). `consigned` is a part the user buys and ships to the board house (a part JLCPCB can place but does not stock; ADR 0084): ask the user, never assume one, and say in your report which parts are consigned, because `fab-notes.txt` lists them under `consigned:` and the user registers and ships them. Ask the user before setting any of these.
- A function of a part that this board does not use (a USB port of a processor that is only programmed over a header) is stated `unused .processor.usb` on the board (ADR 0083), so its limits are not judged and its rails do not say `has no source`. State it only when the user says the function is not used: it is an error if anything else on the board uses it. A test pad or a ground return is not a use.
- A part of the design's own that is a resistor, a diode, a switch or a regulator states a `dc` statement so that the DC analysis can see it (`netsmith-write-nsm`); the analysis then writes the currents and voltages the circuit gives and judges the ratings against them.
- A part on a bus states its role (`.spi.role &= SpiRole::Master`), or the board does for a part that can be either (a receptacle such as `UsbC2` passes the bus through and states none to be asked for): the checker then finds a `mosi` on a `miso`, two masters, two slaves on one select, and a row that contradicts the role.
- Statements may come in any order. There is one way to say each thing.

## Done when

`netsmith build` prints no error and no `warning:` you have not told the user about, `netsmith fab` prints `design rules check: passed` for every board, and you can list for the user every note that `fab-notes.txt` raised.
