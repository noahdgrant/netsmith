# Read netsmith's messages

Fix errors one at a time, from the first one. Later errors are often caused by earlier ones. The language guide (`docs/netsmith/LANGUAGE.md` lists its chapters, in `docs/netsmith/language/`) has each message with its cause, under the construct it belongs to.

## The shape

`error: <what is wrong>` then `--> file:line:col` and the source line. The message names the field or path. The caret marks the statement.

## Checker messages (the file is malformed)

| Message starts | Change |
|---|---|
| `... is not a member of this X` (followed by `did you mean` when a member is close) | Take the suggested member, or fix the spelling. Read the part's fields in the guide's catalogue. |
| `... is not defined in any enclosing block; write .x` | Add the leading dot. |
| `... holds Ω, but this value is A` | Use a unit of the field's dimension. |
| `contradiction on ...` | Two narrowings do not overlap. Widen one or remove it. ``... is connected here to ... but `x.usb` is stated `unused` at F:N`` is the same kind: the board says an interface is unused and uses it (ADR 0083); remove the connection or the `unused`. A test pad or a ground return is not a use. |
| `... names a net, and only a board names nets` | Move `.net &=` to the board, through the module's rails. |
| `... is declared by G, which this part provides`, `... is not declared by G`, `... provides G, which has the pin ...`, ``... is a `G`, and no part or module ... provides it`` | A provider (`part X provides G`) must not declare G's members again (narrow them), and a use of G reaches only what G declares; a provider's pin row has G's kind; import a provider's file or name its type (ADR 0068). For a provider of a standard generic (`Resistor`, `Capacitor`, `LinearRegulator`, ...) that includes `.package`, which the generic declares, and `.designator &=` with other letters, which is a `contradiction`. |
| `... is inside X and is not part of its interface: only narrowing (`&=`) reaches inside a module` | Narrow the value with `&=`. To join, relate or default it, use a rail, pin or declared value of X, or declare one in X. A pin of the IC of `Buck<Lt8641>` is joined through `.reg.ic` (ADR 0120). |
| `... cannot be used in a ~> chain` | The part has no `bridge`. Use `~` between pins. |
| `these pins are connected but name their net differently` | One net, one name. Remove one. |
| `cannot connect a X to a Y` | `~` joins interfaces of one kind. Join their pins. |
| `... must be connected (pad N, NAME), but nothing else is on its net` | The part's pin table says this pin cannot float. Connect it, or the datasheet allows it open and the table should say `optional`. |
| `... must be on the same net as ... (X ties them)`, `... is a no_connect pin ... but it is on net ...` | The part has a `tie`. Join the two pins in the board. Leave that pin alone. |
| `... does not exist in package P of X` | The package has no such pin. Drop the connection, or use a package that has it. |
| ``... is a `X` in package `P`, which has no pin table; its tables are for ...``, ``... `.package` is "P", and no row of the `C` catalog is in that package; its packages are ...`` | The package is misspelt or the part has no such package. Take the `did you mean` name, or one of the listed packages, exactly as written (dashes and parentheses included). |
| `the function of ... is a name from the pin table of its part, not text: write NAME, without quotes`, ``... cannot be `F`; its functions are ...; did you mean `G`?`` | Write the function bare, as the part's `fn` list spells it: `.u.pa9.function &= USART1_TX`. `that function is offered only on ...` means the name is right and the pin is not: choose it on a pin the message names. |
| ``... holds a variant of `E`, but this value is text ... write `E::V` ``, ``... `E` has no variant `W`; its variants are ...``, ```V` is not defined here; a variant of `E` is written `E::V`, or import the variant ...`` | An enum value is a name, never quoted: write it with its enum (`Color::Red`, `AssemblyMode::Hand`) with the enum imported, or import the variant (`import std::parts::passive::Color::Red`) to write it bare. A project catalog's enum column holds the variant's name (`Red`, not `RED`). |
| `... has several functions ... choose one with`, `... .function is stated, but ... is a pin of module X and nothing passes it to a pin of a part` | Add `.u.pin.function &= NAME` for the function the pin has in this design. A module's exported pin takes it only if the module writes the equation the message names, `.mcu.p04.function == .scl.function`. |
| `not evaluated: the logic levels of ...`, `not evaluated: the high level from ...`, `not evaluated: the absolute maximum of ...` | A note, not a pass: the checker could not compare the levels (the grounds are different nets, a level has no value, nothing sets the net's voltage). State the missing `.vih`, `.voh` and so on in the part, or join the grounds. |
| `net N: ... .voh is ... but ... .vih needs ...` | A driver's lowest high is below what the input needs (or its highest low above what the input allows). Change the supply of one side, a level shifter, or the part. |
| `net N reaches V above its ground G (...) but ... .abs_max is ...` | The net can go past what the pin survives. The text in brackets says what sets that voltage. |
| `... uses A and B, which share S and run one at a time: ...`, `... uses N of the peripherals of S, which allows M at a time`, `... are both in use, but they share S`, `X in shared S is not a peripheral of P`, `peripheral A lists F, but no row ... lists it` | The first: the datasheet says A and B use the same hardware; move one interface to a shared resource the message says has nothing in use, or drop it. The others are mistakes in the part's own `peripheral` and `shared` statements: fix the line the message points at (it names the nearest name); a row writes a peripheral's function without a kind. `P cannot be F; that function is offered only on ...` names the pins that offer F. |
| `net N joins two different lines of a X`, `net N joins L to L`, `net N joins lines of different interfaces`, `... are both R on one X bus`, `net N carries the L of two slaves`, `... is a K in the table of P, but R makes L ...`, `... R of X requires it` | A bus rule (ADR 0064), from the `lines` of the bus interface in `std::bus`: one line on one net (a `mosi` is never on a `miso`, a `tx` on a `tx`: join pin by pin crossed, or `~` the two `Uart`s), one master and one select for each slave, a pin table that matches the role, a required line left open. The message names the pins; fix the join, the role (`.spi.role &= SpiRole::Slave`) or the row. |
| `net N has two outputs` | Two outputs drive one net. Remove one connection. A pin shown as `` `a.pa2` (`Mcu` function `UART1_TX`, an output) `` is an output because the function chosen for it is: choose another function for one of them. `net N has K drivers and X is not `tri_state``: one of the drivers is a plain `output` among `tri_state` pins; read that part's datasheet, write `tri_state` (with the page) if the pin is high impedance while the part is not selected, else give the line a net of its own. `net N has open_drain ... and a push-pull driver`: an `output` or `tri_state` pin drives a line that an `open_drain` pin pulls low; give it its own net, or write `open_drain` if its datasheet says so. `... and no pull-up`: add a resistor from the line to a rail's `pos` or to a pin that drives it high. |
| `X is an output on net N, the net of rail R` | A push-pull `output` is tied to a rail, which is a short (#461). Give the pin its own net; if the datasheet says the pin may be tied (a GPIO strapped to ground), its kind is not `output`: write `bidirectional`, `open_drain` or `passive` as the datasheet says. Any other kind may be tied to a rail with no statement. |
| `... are both headers`, `... both sockets`, `... has N positions and ... has M`, `... has a pitch of A and ... has B` | The two mated connectors do not fit: a header goes with a socket, with the same positions, rows and pitch. Use the matching part. |
| `contact N of the mated connectors ...` | The boards disagree about what contact N is: ground against power or a signal, two outputs, or an input nothing drives. The message names the pin and net on each side; fix the wiring of one connector. |
| `the mate of ... carries power or signals ... but no ground`, `... are already joined by the mate of ...` | Wire a ground to a contact of both connectors; remove the `~` between ports that the mate already joins. |
| `... is inside ..., a X; a system can reach only the .mating of a connector` | A system mates connectors and names no pin: join `.board.connector.mating` to another. |

## Solver messages (the file is fine, the numbers fail)

| Message starts | Meaning and change |
|---|---|
| `the X catalog has nothing for P, which needs ...` | No real part lies inside the ranges. Loosen the range or pick another value. The location points into the library, because the part is what has no candidate. |
| `no X candidate satisfies P: the closest ...`, `no combination of candidates satisfies A and B together` (the same, for parts that depend on each other; `..., whatever the other parts of the group are` means only A and B are the fault and the rest of the group is not), ``no G provider satisfies `P` at file:line: none of the N in scope works``, then an indented list, one entry for each provider in the order tried (`Q (the closest):` marks the one with the fewest failures; `not tried` means the search never reached it), with its reason under it and, for a provider whose own catalog pick failed, a sub-list `closest of the N that fit: <row>` and `fails because: <requirement and numbers>` | Candidates fit, but a relation fails. The text names the closest one (for a generic G: every provider in scope, each with its reason) and the relation with its numbers. Loosen the requirement, tighten a tolerance, change the circuit, or import the file of another provider of G. |
| `... is unknown for some candidates` | The capacitor catalog has no bias curve for some parts, or the bias is unknown. Place the capacitor between a rail's pos and neg, or state `.bias`. |
| `... must always be at least / at most ...` | A bound fails in the worst case. The numbers show by how much. With `: it is held to M (`.x &= .m`, F:N), and `.m >= E` (F:N) bounds it` the bound is on a member M that the part is held to: the part's row or stated value cannot meet it; change the bound, the part's value, or the statement that holds it (ADR 0065). Two of them come from a datasheet's own condition: `q.gate_source_voltage must always be at least q.on_resistance_vgs` means a MOSFET's `.on_resistance` is guaranteed only at a higher gate drive than the board gives (pick a logic-level part, raise the drive, ADR 0092), and `stage.on_time must always be at least stage.buck.min_on_time` (or `off_time`, `min_off_time`) means the buck IC cannot switch that briefly at the highest input and lowest output (lower the frequency, narrow the input range or pick another IC, ADR 0093). |
| `... the low end of the range is above the high end: A against B` | A range with a value at an end (`.vcc.current &= .min .. .max`, ADR 0066) works out to a low end above its high end: the two ends are in the message. Fix the value that is wrong. A range whose end has no value is not an error but a note: `not evaluated: x.vcc.current &= (x.min..x.max)`, which says the range claims nothing until the end has a value. |
| `the currents on net ... do not add up`, `the currents at the join ...` | Load and supply disagree. `must stay within A, but the others on it work out to B` means a stated current is a budget and the circuit draws more (ADR 0038); a stated range need only contain what the rest of the net determines. Check the stated draws and the supplier's `max_current`. `the currents at the join` is the same between two boards: they disagree about a port's current. |
| `no header candidate satisfies ...: ... (N * X.mating.pin_current) must always be at least ...` | The contacts of a mate cannot carry the rail: N is how many contacts carry it and the rating is the datasheet's. Use more contacts for the supply and the ground, or a connector with a higher rating. |
| `gave up after trying N combinations of candidates for `a` and `b` ...` (with `(the search stopped for the work it had done ...)` when the board is large) | The parts named are searched together because a bound reads values of all of them, and no one of them is the cause. State a value for one of them, narrow a window that a bound on them reads, or split the group so that fewer parts share a bound. |
| `gave up after trying 64 provider combinations for ...` | Import fewer providers or name one as the type (`.rf: AcmeMicroCoax`). |
| `... name the part with .mpn: A, B` | The part's catalog is keyed. State `.mpn &= "A"`. |
| ``... is held by `.lcsc &= "C..."` to a row of the X catalog, and the catalog has no row with ...`` | A hand pick (ADR 0122) names a number no row of the part's catalog has. Fix the number, add the row with its source (`netsmith-dev-add-part`), or remove the narrowing to let the solver pick. With `.lcsc` and `.mpn` both, they must be numbers of the same row. |
| ``... is held by `.lcsc &= "C..."` to one row of the X catalog, and no other row was tried for it`` | Follows a failed relation: the hand-picked row does not meet the design. Change the design so the row fits, or change or remove the hand pick; it is the user's choice of part, so ask before you drop it. |
| ``... is locked to `A` and was picked as `B` `` (a note) after you added a hand pick | The hand pick comes before the lock, which still records the old row. Run `netsmith lock --update` and commit the lock. |
| ```x.lcsc` holds the part to a catalog row, but `x` (`K`) picks from no catalog`` | Only a part with a catalog has rows. Remove the narrowing. |
| `X.picks.toml: netsmith no longer reads a picks file (ADR 0122) ...` | The file held hand picks once. Write each narrowing the message lists in the body of its board (`.boot1_cap.lcsc &= "C307331"`), delete the file, and check that `netsmith lock --check` still passes (the rows are the same). |
| `... rows were left out because package P has no pin` | No catalog row's package has a pin the board connects. Use another package or leave the pin unconnected. |
| `... cannot be chosen from the X catalog: F:N: ...`, `F:N: the row for ... has no source` (or `... is already a row at ...`, `... library ... is not Basic ...`) | A catalog file is wrong at line N of file F: a column the part does not list, a cell in the wrong unit, a missing column or source, a repeated part. Fix the file. |
| `pad N of X is given to both ...`, `... have no pads` | A fault in the part's `pins` table: fix the table. |

## Design-stage and fab messages

- `does not say how it is made`: add `import std::mfg::jlcpcb::TwoLayer` and `.process: TwoLayer`.
- `process.inner1 ... has no net`: name the plane's net on the board.
- `there is no KiCad symbol for a X yet`: the mapping (`std/kicad.toml`, and the project's `kicad.toml`) has no row for this kind. Add a `[[part]]` row with the symbol and footprint, and a `[[library]]` for the library that holds them if it is the project's own.
- `symbol library L not found` / `footprint L:F not found`: `build` and `fab` read KiCad's libraries; when the message says `no KiCad ... libraries found` and lists the places looked at, install KiCad 9 or set `NETSMITH_KICAD_SYMBOLS` and `NETSMITH_KICAD_FOOTPRINTS` to the folders that hold them, or list the library in `kicad.toml`.
- `--cross-check` reports `DIFFERENCES`: a layer, drill file or placement differs from KiCad's own plot, or a design rules finding is only netsmith's or only KiCad's (the lines say which, with the rule and the place). Open the `cross-check-<file>.png` written beside the package (grey both, white only netsmith, dark grey only KiCad) and report it as a bug in netsmith's writers. A `note:` line under `the files agree` names a known difference of the KiCad release that the check allowed for (ADR 0034, "Known differences of a KiCad release"); it is not a failure.
- `the board outline on Edge.Cuts is not closed`: the outline of a ported board has a gap; the message gives the coordinates.
- `N part(s) have no LCSC part number, so JLCPCB cannot assemble them` (`fab` stops before placing anything and lists every such part with its designator, path and what to write): a catalog row without an `lcsc` was picked for a part the board house is to assemble. Say who does assemble it: `.<part>.assembly &= AssemblyMode::Hand` in the board for a part the board owns (`AssemblyMode::Consigned` if the user buys the part and ships it to the board house, ADR 0084: ask, do not choose); for a part inside a module, the line in the module's definition or its `.assembly_mode` that the message names; or `hand` in the row's `assembly` column. Or give the row an `lcsc` that has a recorded source. `fab` has no flag for it.
- `N connections could not be routed (...)` with `net X: A.1 to B.2` lines: the router gave up on those connections. `fab` still writes the board file, the Gerbers and `fab-notes.txt` into the output folder, marked `INCOMPLETE`, with `routing-failure.txt` listing each connection, its net and its two pads (open the board file in the PCB view to see the part that is routed; do not order from the Gerbers), and the run still ends in this error. If it says `stopped after the route timeout`, raise `--route-timeout <secs>` (default 300; `0` is no limit); otherwise the lines are ones it cannot route (a pad walled in by its neighbours where the process or the board refuses a via in the pad, a crowded board): give the parts more room, narrow the process's track and space within the factory's limits, or move the pads named. To choose which, read the end of `routing-failure.txt`: for each line left, the stage of the router it last failed in and the nets whose copper stands in its way (a line with no net in its way is walled in by pads, holes or the edge alone); `routing-report.json` has the same and a crowding map (`crowding.counts`, 1 mm squares from `crowding.origin`, row by row), whose highest squares are where parts need more room.
- ``N part(s) do not fit the outline of W x H mm: outside the outline or inside its margin, by mm past what is kept clear: `header` (J1) 1.30, ...`` (PROVISIONAL): the placer ended with those parts outside or overlapping, and the line names every one by its member path with the designator beside, and with how far. The full list, with every part's position, turn, face and state, is in `placement-failure.txt` in the board's fab folder (the message names it). Give the named parts more room (a larger outline, the other face, a part with a smaller courtyard) or loosen a requirement that holds one of them. `the parts need X x Y mm ... over in y` appears only when the courtyards alone are more than both faces hold; then the outline is too small whatever the placer does. A part that states a rotation is not turned to fit, and the message names it with the one turn it has. When the physical file has requirements and the placer could not meet them, the first error (and the same text in `placement-failure.txt`) starts `no placement meets every requirement of the physical file:` and lists `these lines cannot both hold: <file:line `text`>; ...` (only where proved: a relation against the windows of its parts, two windows whose courtyards always overlap, a window inside a keepout or a cutout, a face against a height limit, two relations of the same parts, a window outside the outline) and then each requirement not met, with its measured value, window and how far out (PROVISIONAL, ADR 0045 section 13); with no `these lines` the cause is not proved, so change the line it names, not a guess. The same block is printed at once, before the placer starts (no `placement-failure.txt`, no `the placer made N tries`), when the lines alone prove the conflict (ADR 0045 section 14); `build` and the editor's findings (`constraint`) say it too. A part the lines pin past an edge nobody stated (```plug` (J1) is not wholly inside the board outline: its courtyard is ... past the right edge ...``) and a part bigger than the outline in every turn (`... a part is bigger in every turn it may take: ...`) are refused the same way. With `--constraints warn` the conflicting lines are warnings and the placer runs. Each hole pair is listed once, by pad. A last line `the placer made N tries ...` says the placer ran again from other seeds (and with the largest parts in corners first) and shows the closest run; a shortfall under a hundredth of a millimetre is shown with its digits (`0.004`), not as `0.00`. ```reg` (U1) lies over the pins of `socket` (J1), whose pins protrude 0.60 mm (file:line), and that is not allowed: ...`` (ADR 0045 section 15) means a `.pin_protrusion` line is not enough: the stack is too tall (it gives the protrusion that fits), the part states no height, or the board house assembles it. Change the number only if the drawing says so; never state a protrusion to clear a finding.
- A design rules failure stops `fab` (`the design rules check found N violation(s), M unconnected pad(s)...`). Each line names the rule (`clearance`, `hole_to_hole`, `copper_edge_clearance`...), the numbers (the distance found and the least allowed), the place in mm and the items (`SMD pad 1 [VIN] of C1`). Fix the board or the placement; `--allow-drc-violations` packages anyway and the notes say `NOT clean`. KiCad is not needed to run the check.
- `[constraint]` findings (`constraint usb.place.left (widget.physical.nsm:14) is violated: ... it allows -0.55 to -0.45 mm (0.73 mm over)`) are the board's own requirements on where a part goes (ADR 0045) and stop `fab` like a design rules error. Each names the line, the part, the drawing it measured (`F.Fab`, `F.CrtYd` or `pads`), the measured value, the window allowed and how far over. Change the range or the circuit, not the layout file. `netsmith-use-constraints` has the loop. `--allow-drc-violations` does not waive them (the error says so); `fab --constraints warn` lists them as warnings for one run, `--constraints error` forces errors over a manifest's `constraints = "warn"`.
- `... is physical intent, and a board's circuit source does not hold it (ADR 0048); declare it in ... `physical for Board` in `x.physical.nsm``: the outline, a cutout, a mounting hole, a fiducial, a label, a keepout the board draws or a `.place` requirement was written in the board. Move the lines to the board's physical file (`case { }` for the first five; the message names the unit and the file). `... is not physical intent: a physical file states where a part is ...` and `a physical file states where things are, and a connection with `~` changes the circuit`: a statement in the physical file sets something other than a `.place`, a `.height` or what the file declares; put it in the circuit source. `physical for X names no board of the source it is paired with; its boards are ...`: the unit's name is not a board of the source beside it. `... belongs in the `case { }` section of `physical for B``: wrap that declaration in `case { ... }`.

## Warnings: guidelines

`warning: B: IPC-2221 guideline: net N carries up to I (...) but its tracks are W mm wide ...` is the track width check (ADR 0036). netsmith draws a net no rail states a width for at the width IPC-2221 needs, so the warning means a rail's `.min_track` is narrower than that, or a current on the net is unknown (a `note: the current of ... is not known ... tracks of net N are not sized` comes with it: state that current). It gives the net's worst-case current (the sum of the loads on it or returning through it, all on at once; the message lists the largest terms), the width it is drawn at, the copper and temperature rise (10 K unless the board states `.process.max_temperature_rise`), what that width carries and the width IPC-2221 needs. It is a guideline and not a fabricator's limit, and IPC-2221 is conservative: widen the rail's `.min_track` as the message says (or remove it, so the router sizes the net), or state the higher rise you accept. With `guidelines = "error"` in `netsmith.toml` or `--strict` it is an `error:` at the rail's line instead. `fab` also writes it to `fab-notes.txt`. `warning: B: unconstrained pick guideline: `r` (Resistor) was chosen with nothing limiting its resistance, so the solver took the first row that fits, ROW ...` means a resistor, capacitor or inductor got the first row of its catalog because nothing limits its value (ADR 0065): state it (`.r.resistance &= 4.7kohm +/- 5%`, or the member the message names), bound a value it decides, or write a range for "any" (`&= 10kohm..100kohm`). If it adds `limited as a ratio, not in size, by ...`, the bounds it names hold at any size (the `.out` of a divider): state one of the resistors, or bound a value that changes with the size (a current, a voltage the design checks). `warning: B: unstated value guideline: `m.x` is declared by `M` and nothing states or works it out, so the checks ... are not evaluated` means a check waits for a value nobody gave: state it where the module is used. Both are errors with `--strict`. `warning: B: unresolved generic guideline: L1 (path): the solver kept a generic part because no row of the `inductor` catalog can be ordered for 1 uH 30% 0402, saturation current at least 6.05 A. Nearest in the catalog: ...` means no catalog row meets the need the design recorded for that part (the need is in the message), so `fab` will refuse the board (issue #182). The nearest rows are ranked by how near they come to the need that fails, with what the board's checks say with each in the part's place: add a row that meets it to the project's catalog (`netsmith-dev-add-part` for a real part, with its source), or change the design so that an existing row does. A part with `.assembly &= AssemblyMode::Hand` or `AssemblyMode::None` is not reported; it is an error with `--strict`. `warning: B: bus role guideline: X is bidirectional in the table of P, and R makes L ...` asks the part to write the kind its datasheet gives (`input`, `output`, `tri_state`; for a peripheral's function, `F:input`), and `... X is joined to another end of a B bus and states no role ...` asks it to state `.x.role &= ...` as its datasheet says (a connector the bus goes through, such as `UsbC2`, states `UsbRole::Passthrough` and is never named: the message is about the end behind it); `--strict` stops on both.

## Notes are not errors

`note: not evaluated: ...` means a relation waited on a value nothing set. `` `p.current` is stated A, but the DC analysis of the circuit around it finds B: at most X at the high end with u at 16V ``, and a failed rating that adds `(the DC analysis puts `p.current` at ..., its high end with ...)`, come from the DC analysis of the resistors, fuses and diodes between the board's supplies (ADR 0076): the circuit needs more than the range you stated (a budget) or than the rating allows, and the states name what gives it; change the circuit or widen the statement. `the source cannot give what `reg` asks (5W at its output, efficiency 90 %): its input falls to 0V and no operating point exists, with supply at 10V` means a regulator's output asks for more power than the supply can give through the fuse, the diode and the other parts in front of it, in the states it names: lower the load, raise the supply or the efficiency, or lower the resistance in front (ADR 0076, amendment 3). A regulator whose input is below its minimum fails the relation the part states for it (`.vin.voltage >= ...`) with the voltage the analysis gives. The same holds for any rail on a `~>` chain from a supply: its `.voltage` is the node's (the supply less the drops of the parts in series), so a failed `.vout.voltage >= 4.5V` adds `(the DC analysis puts `p.vout.voltage` at 4.22V..4.94V, its high end with ...)`; do not restate the drops with `.vout.voltage == .vin.voltage - .fuse.drop` (ADR 0076, amendment 5). A connector's supply is a source only when its part states `dc source` (`Obd2M`, `UsbCPower` do) and the board states its `.voltage`. `note: the DC analysis left the network of ... to the bound from Ohm's law` means an island has too many corners to solve: cut it at a node a rail holds. Other notes that begin `the DC analysis left the network of ... alone`, `found no operating point for the network of ...`, `could not solve the network of ...`, and `does not model the current of ...` say a network was not solved and what to change: the load of a regulator is not known or is pushed back from a higher voltage (state `.vout.current &= -200mA..0A`, or fix the net that drives it), no state of a switch or diode is the circuit's (a source follower: change the gate drive), or a diode joins two nets that sources hold (state its current). Nothing is written for those parts, so their ratings are not judged by the analysis. `not chosen: ...` means a part got no pick. Decide whether either matters for your board. `note: reg is a G: picked P; passed over Q (why)` says which provider of a generic was taken and why the ones before it were not (ADR 0068): fix nothing unless the pick is not the part you want; then name it (`.reg: P`) or state a requirement. `note: these values depend on each other ...` names a circle (a regulator's input current needs its input voltage, which needs the drop of that current): nothing in it passes. State a range on one field with `&=`, or state the range the part works in (`.vin.voltage >= 3V`, `<= 65V`) and the supply's, and the solver starts it (`note: ... so the solver started it from ...`, ADR 0053); never state the part's whole range as a start, which stays as loose as written. When a check that reads the circle is not evaluated (a rating that needs its current), the build also prints `warning: B: open circle guideline: ...`, which names the check and a field to start from, and under `--strict` or `guidelines = "error"` stops (ADR 0057); if it says the circle "also reads `x`, which nothing states", state `x` first. If it says "net `N` carries 3 currents (...), none of which has a value", the circle runs through a net where the solver cannot work out a part's current (ADR 0026, issue #18; a divider behind a fuse, a diode or a resistor, whose draw you limit): the limit is not applied to the pick. State a range on the part's current it names (what the loads behind it draw at most and at least), on the current of the rail that supplies the net before it (negative, since a supply counts negative: `.supply.current &= -8mA..0A`), or a voltage in the circle; a range on a load joined with `~` onto the net does not start it (the guide's _The sign of a current_), or `x.current &= 0A` on a rail of the net that nothing else draws from, and then a voltage. `note: not evaluated: the role of X is not stated ...` says one part of a bus states its role and another does not, so its table and the limit are not judged: state it. `note: R5 (`path`) is C123 (MPN), and its catalog row (file:line) states a stock of 0: the solver does not read stock, so it picked the part; ...` (or `... data/jlcpcb/considered.csv records it as out of stock when it was read, and a catalog of this project offers it`) names a part the solver picked from a catalog row that says it has no stock (issue #176). The pick is the same as without the note, and it is not a guideline: choose another row of the catalog (remove the row, or put the one you want first) or state a different value, then read the supplier's stock. An empty `stock` cell says nothing and gets no note.

`note: the balance on net X is incomplete: P is not modelled, so Q is not set from it` means a pin on the net is neither a rail, a counted chain, nor a part that draws nothing, so the current of the part Q is not worked out by subtraction from the others. State Q's current, or give the part at P a `current` in a chain or a `Rail` of its own (ADR 0027). An `input` pin (an enable) of a part that has a `Rail` is not listed; one on a part with no `Rail` is.
