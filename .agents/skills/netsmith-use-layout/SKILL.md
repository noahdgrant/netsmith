# Use the layout file

The layout file, `<stem>.pcb.toml` beside the source, holds the **solution**: where each part is, its turn, its face and whether it is locked. The physical file holds the **requirements** on where a part may be (`netsmith-use-constraints`); a requirement never goes in the layout file, nor a solved position in the physical file. The guide's section "The layout file" (`docs/language/23-the-shape-of-a-board.md`) has the format, the frame and the seed rules. `netsmith layout --help` and its subcommands' help have the flags.

A part with no entry is placed by the placer round the parts the file places; a part with `lock` is left where it is; any other entry is where the placer starts from, and moving a part by hand moves nothing else.

## Loop

1. **Read what is there**: `netsmith layout show --format json` (a PATH, a part's path or a module's, narrows it; `--board NAME` and `--file FILE.NSM` pick the board). It gives each part's `path`, `refdes` and `entry` (`at`, `turn`, `side`, `lock`, `source`, `line`); a part without `entry` is the placer's. A path the board lacks is refused with the nearest names. Paths are the design's (`stage.output_cap`, `decoupling[2]`), never a designator: a renumbered designator changes no path.
2. **Decide what is the user's**. Lock a part when the user, a drawing or a mechanical fit fixes it (a connector at the case edge, a part under a button). Leave every other part with no entry or unlocked, so the placer keeps shaping the board round them. A board with every part locked has nothing left to place.
3. **Write the entry**: `netsmith layout set <path> --at X,Y --turn 90 --side top --lock`. Use `set`, not the TOML: it reads and writes the file as the editor does, refuses a bad path or turn with the file untouched, and keeps the other tables and the file's comments.
   - Frame: millimetres from the outline's top left corner, x right, y down. `--at` is the **footprint origin**, not the body or its centre; a requirement measures the body, so convert from a drawing's body numbers with the footprint's own offsets, and let `layout check` confirm.
   - `--turn` is any angle from 0 up to 360 (90, 45), counterclockwise as seen on screen from above; the placer turns by right angles only (by 45 degrees a part whose `.place.turn_step` is 45), and the editor's part inspector takes any angle in its turn field.
   - `--side bottom` is the top footprint mirrored left to right, then turned as seen from above.
   - A new entry needs `--at`; on an existing entry a flag left out keeps its value, and `--unlock` clears the lock. A new entry is `source = "hand"`.
4. **Check**: `netsmith layout check` (exit 1 on an error, notes do not change it; `--format json` has `ok` and `findings` with `severity`, `kind`, `path`, `line`, `message`). It places nothing and needs no KiCad. Kinds: `no_part` (an entry the board has no part for: the part was renamed or removed; fix or delete the entry), `bad_turn`, `bad_place`, `requirement` (a locked entry breaks the physical file, in `fab`'s words), `placement` (a fault of `fab`'s own placement check among the parts the file places: courtyards that overlap, each shape of a part's several courtyards counted as its own, a part past the edge, in a keepout or cutout, too tall, a hole too near; the same sentence `fab` stops with, and its data in `fault`), `no_entry` (a note), `unmeasured`. A clean `layout check` means `fab` refuses nothing the file decides; what is left is the placer's (the parts with no entry). `set` says a `requirement` finding of a locked entry it wrote, and a `placement` finding of any entry it wrote, as a warning.
5. **Place round it**: run `netsmith board build`, then `netsmith board fab`. A build puts every part with an entry where the file says. `fab` says which seed placed the board (`placed on ... with seed 15`) and, when it is not the file's seed, writes the new seed into the layout file: review that diff, and commit the file with the source. `board fab --locked` writes nothing and stops instead when the seed would change; use it in a release or a check, and run plain `fab` to take the new seed.
6. **One module again**: `netsmith layout regenerate <module path> [--seed N] [--margin MM]` places the module's unlocked parts again inside the box round them, every other part held, and prints what moved, the nets whose copper is routed again and the findings before and after; nothing is written without `--write`. A proposal is a proposal: keep it only when its findings and totals are better. The editor keeps the router's copper in `.netsmith/routes/` (never committed), so a route after the change routes only the module's nets again; the proposal's `kept copper` line says which nets keep theirs, and `board fab --reuse-routes` keeps them too (plain `fab` routes every net).
7. **Freeze the result**: `netsmith layout capture` places the board as `fab` does and writes an entry for every part (a part with an entry keeps it, with its `lock` and `source`; the others get `source = "auto"`, unlocked) and the seed that placed the board; `--dry-run` says what it would write. Use it when the user wants a placement kept as it is, so a later change of the placer, a catalog or the circuit does not move a part; review the diff and commit the file with the source. It refuses a board no seed places and writes nothing then.
8. **Find a place for one part**: `netsmith layout fit <path> [--near <part|X,Y>] [--side top|bottom] [--format json]` tries the part on a 0.5 mm grid (`--step`) for each right-angle turn and face, with every other part where it is, and gives for each pose the nearest place where the placement check (the one `fab` and `layout check` run) and the physical file's requirements find nothing, with the `layout set ... --lock` line that writes it, or the closest try with what is in the way. Write the line as given: locked, `fab`'s placer places the other parts round it; an unlocked entry is put where it says after placing, and a part with no entry may be placed there. It writes nothing; exit 1 when no pose fits. Use it instead of searching the board yourself. `--as-laid-out` places nothing and queries the board exactly as the layout file has it (milliseconds; every part needs an entry, run `layout capture` first, and the outline's size must be stated): use it on a board that is slow to place. Without it the placing prints its progress on stderr (`--progress json` for JSON lines, as `fab`), and a `note:` first says when every part has an entry and `--as-laid-out` would answer at once: then rerun with it. The editor's `GET /api/pcb/fit?board=&part=` is the same query.
9. **Move parts in KiCad**: when the user wants to drag parts with KiCad's tools, or to see a placement that `fab` refuses, run `netsmith layout export --kicad-pcb kicad/<stem>.kicad_pcb`. It writes the placed board with no copper whatever the placement check finds, marked not for fabrication, with the findings in `<stem>.findings.txt` beside it; never order from it. The editor's PCB view has the same files in one zip as its "Download KiCad board" button. After the user moved parts there, `netsmith layout import kicad/<stem>.kicad_pcb --dry-run` says which parts moved, and without `--dry-run` writes them (moved parts as `layout set` writes them, the placer's parts held where they are with `source = "auto"`). Parts are matched by the hidden `netsmith_path` property, not the designator; tell the user to move parts, not the outline. Then `layout check` and `fab`.
10. **Look**: `netsmith layout summary --format json` gives the placement as numbers (wire, crossings, decoupling distances, each module's box and intruders, the area used and the free rectangles of each face, each net's longest line, and what each guideline of the parts' `layout` blocks measures with the number it asks for; `--near <path> --within MM` lists the parts near a part, courtyard to courtyard, and `--between U1.3 C1.1` gives the distance between two pads, centre to centre and copper to copper); the editor's Summary tab shows the same. `netsmith view 3d <file.nsm> --view top --highlight <path> --picture board.png` (`--highlight module:<path>` lights all the parts of a module, each module named in its own colour, to see how far a module spreads; `netsmith view pcb --highlight module:<path>` draws the same in 2D), and `netsmith dev board3d <file.nsm> --format json` for numbers (see `netsmith-use-constraints`, steps 9 and 10). Quote numbers from the data, not from the picture.
11. **Read the geometry**: `netsmith layout parts [<path|designator|module>...] [--as-laid-out] --format json` gives each part's `frame` (`at`, `turn`, `side`, `mirrored`, size), its courtyard as `courtyards` (shapes, on the board; `local_courtyards` in the footprint's frame) and its `pads` (`number`, `net`, `at`, `local`, `width`, `height`, `bounds`, `copper`, `drill`), with the placement's findings beside them (`placement`, `conflicts`, `placement_refused`), also for a layout `fab` refuses; exit 0 whatever they are. Use it to compute a distance, a gap or where a pad goes for a place before trying it (the guide's "Each part's geometry, as data" has the rule and an example); do not start the editor or read the `.kicad_pcb` for it.

## The schematic's arrangement is another file

`<stem>.sch.toml` (the schematic layout file) says how the *drawing* is arranged, never where a part is on the board; `netsmith schematic` is to it what `layout` is to the layout file. `netsmith schematic show [--format json]` lists the sheets (a module instance, or the parts the board declares itself) with where the drawing puts the box of each on a big board (more than 16 parts), and each entry with its line and whether the drawing uses it. `netsmith schematic set stage.output_cap --by 2.54,0 --rotate 90` writes a part's entry (lengths on the 1.27 mm grid, x right, y down; `--by` is from where the drawing puts the block, `--pin X,Y` from the sheet's reference part), `set stage --at 101.6,0` places a sheet's box, `--clear` removes an entry; the other tables and the comments are kept and a bad name is refused with the file untouched. `netsmith schematic check` (exit 1 on any finding) lists the entries that name no sheet or part and those the drawing could not honour (a block on another part, a box on another box), and `netsmith schematic arrange [--reset] [--write]` says where the drawing sets each sheet's box and, with `--write`, keeps it as `at` entries. Arrange, look at the drawing in the editor, arrange again; commit the file with the source.

## When the layout and a requirement disagree

- A locked entry that breaks a requirement is refused before placing, with the numbers. Change the entry (`layout set ... --at`), or `--unlock` it so the placer finds a place that meets the requirement, or ask the user whether the requirement is wrong. Never loosen a requirement to keep a lock.
- A locked part whose courtyard is past an edge needs the requirement that says it may hang over (`netsmith-use-constraints`, overhang); the lock does not say it.
- Two parts locked so that their courtyards overlap is a placement fault that names both, which `layout check` finds before anything is placed. Move one (`layout fit` says where it fits).
- A board placed with a fault of where its parts are (an overlap, a part past the edge) is not placed: `fab` refuses it and `dev board3d` ends with 1, its faults in `placement`.
- `no seed places the board: ... the closest is seed 7, where this blocks it:` lists what blocks the best try, by path and designator, with the amounts. Unlock or move the part it names, or give the board more room; `--place-seeds N` and `--place-budget` widen or bound the search for one run.
- Entries of parts that `netsmith routes import` wrote are `source = "import"`; they may share courtyard area and `fab` warns of each overlap.
- `warning: B: layout guideline: `reg.ic` (U1) asks for `input_cap` within 2 mm ...` is a part's datasheet guideline (its `layout` block) that the board does not meet. Move the part it names as it says (`layout fit` finds a place), or, when the user decides the board is right as it is, write a waiver in the layout file with the user's reason: `[B.waive."reg.ic.input_cap"]` and `reason = "..."`. Never write a waiver without a reason the user gave; `fab` then says the guideline is waived and neither warns nor stops.
- The same `waive` table waives a design rules finding of a part's own footprint (`(within U1's own footprint)`), keyed by the part's path and the rule: `[B.waive."reg.ic.pad_to_pad"]` with `reason`, `source` (the datasheet's land pattern) and `pads = ["2", "3"]` or `at = [x, y]`. Only with the user's decision; a waiver that covers nothing is `error [unmatched_waiver]`.

## Report

Tell the user which parts you locked and why, which you left to the placer, each `layout check` finding left with its line, the seed `fab` wrote if it changed the file, and the seed `layout capture` wrote if you froze the placement. To rearrange one module, run `netsmith layout regenerate <module>` (a proposal: what moves, the nets routed again, the findings and totals before and after), try other `--seed`s, and keep the best with `--write`; its parts get unlocked entries with `source = "regen"`. Tell the user which seed you kept and why.
