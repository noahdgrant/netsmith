# data/jlcpcb: sourced JLCPCB/LCSC parts

`catalog/*.csv` hold the LCSC ("C") numbers that netsmith offers: one file for each catalog (`resistor.csv`, `capacitor.csv`, `led.csv`, `ldo.csv` and the eight of the standard kinds below, `lmr16006y.csv`, `rt8059.csv` and `tps54202.csv`, one buck converter IC each, `sn74lvc1g04.csv` and `attiny13a.csv`, one row each for the ICs of `std/parts/logic.nsm` and `std/parts/mcu.nsm`, and `level_translator.csv`, `lt8641.csv`, `supercap.csv` and `cell.csv`, which have a header and no row), one row for each part. `considered.csv` holds the parts that were looked at and not offered, with the reason.

**Price and stock are not shipped.** The `price`, `stock`, `date` and `checked` cells of every row, and the `stock`, `unit_price_usd` and `checked` cells of `considered.csv`, are empty, because a supplier's price and stock go stale within days. A price and a stock come from a supply provider when the bill of materials is made (ADR 0047); an empty cell means unknown, never zero, and the solver does not read these columns at all. A part's availability, price and library type must be read from the supplier (JLCPCB's parts page, LCSC's page for the number) before ordering. What the files do record is the identity of each part: its LCSC number, manufacturer's number, package, library type (Basic or Extended) as it was read, the electrical values from the record or datasheet, and where they were read.

## The files

A catalog file is CSV whose first line names the columns of the part's `catalog X { ... }` declaration (the field path without its leading dot) and the fixed columns `lcsc`, `mpn`, `name`, `label`, `library`, `price`, `stock`, `date`, `source` and `notes` (and, optionally, `manufacturer`, below). The format and the rules are in ADR 0022 and `docs/LANGUAGE.md` (Catalog files). In short:

- **The order of the rows is the selection policy.** The solver takes the first row that works and nothing sorts the file. These files are written Basic first (Extended parts cost a feeder fee), then in the order of the unit price read on a past date, then by ascending value, so the solver takes the cheapest Basic part that works. **The prices are not shipped, so that order was set from prices read on a past date and cannot be re-checked.** A test checks the part that can still be checked: every Basic row comes before every Extended row. When you add a row, put it after the Basic rows that cost less and before those that cost more, using the price you read at the time; and keep Basic rows before Extended ones.
- **`resistor.csv` has a `temperature_coefficient` column and every cell is empty.** No datasheet figure for it has been recorded for these rows, and a value enters a catalog only with its source (add it with the `netsmith-dev-add-part` steps). A design that bounds the field is offered no standard row until a row states it.
- **`capacitor.csv` has a `dielectric` column, filled for all 61 rows from the class that JLCPCB's record prints** (the `name` cell and the `JLCPCB lists ...` line of `notes` carry it, and the two agree on every row): `C0G` for 20 rows, `X5R` for 14 and `X7R` for 27. The cell is the variant name of `std::parts::passive::Dielectric`. No row was read for a class from a datasheet or from memory, so a row whose record names none would be left empty. A generic capacitor has no dielectric, so a design that states one is given a row of this file (ADR 0055).
- **`inductor.csv` has an `rms_current` column and every cell is empty.** The `notes` of the four rows mention a temperature-rise current (Irms): 2.4 A for the Chilisin row, whose rise the note does not state, and 700 mA, 1200 mA and 1000 mA for the three Murata rows at a 40 K rise. The rises differ between makers, so those numbers are not one rating, and none was entered: a value enters a catalog only with its source and the rise it is for (add it with the `netsmith-dev-add-part` steps, and put the rise in the row's notes). A design that bounds `.rms_current` is offered no standard row until then.
- **`tvs.csv` has a `breakdown_voltage` column (the minimum VBR) and only the SMDJ36A row states it (40 V at 1 mA, from the Littelfuse SMDJ series datasheet table).** The `notes` of the MDD rows carry the JLCPCB record's other figures, but not as a column a datasheet table was read for, and a value enters a catalog only with its source. A design that states `.breakdown_voltage` is offered no other standard row until then, and gets a row from a project's catalog that records one (ADR 0073).
- **`temp_min` and `temp_max` are fixed columns** (ADR 0099, provisional): the lowest and the highest temperature the part works at, each one temperature as the record or the datasheet prints it (`degC` is read since ADR 0103, `-40degC` and `85degC`; the cells written so far are kelvin, `233.15K` and `358.15K`, which is the same value, and a new row may use either). A board that states an `.environment` is checked against them: a row whose range does not cover it is not offered, and a row with an empty cell is offered and named in a guideline finding, so an empty cell is the right way to say that no document was read. A cell is filled only from a figure that a record or a datasheet prints, the row's `source` says which (`temp_min, temp_max:` and the record's date or the datasheet page and table), and its `notes` say which temperature the figure is when the document says (ambient, junction or operating) or that it does not. Never write a figure into a cell from a package's class, a part's family or memory. (A dielectric class has its own, separate table: a capacitor row that names a class in `dielectric` and leaves `temp_min` or `temp_max` empty is judged by the class's cited range, `CLASS_RANGES` in `crates/netsmith-check/src/environment.rs`, and the check's messages say "from the class X7R". The table has X5R (-55 to 85 C), X7R and C0G (-55 to 125 C), each from the makers' documents named in its doc comment, read 2026-11-11: Murata C03E, Samsung's MLCC catalog of November 2015, Yageo's X7R datasheet V.26. A range of that table is a property of the class code and not of a part, so a figure read from a part's datasheet goes in its cells and always wins; all 61 capacitor rows state their own range, so no standard row is judged by the table today, and a test checks that no row's own range is wider than its class's.) **360 rows state them, 345 of them read from a datasheet (330 read 2026-11-10, 11 read 2026-11-11, 4 read 2026-11-16: the AO3401A and the three two-row headers) and the fifteen rows of `crystal.csv` from the JLCPCB listing text** (the FC-135 and the 25 MHz YXC datasheets print the same figure as their `T_use`, the series sheet of the other two prints it as the standard one, "or specify"; the cells are the listing's): the crystals' `-40℃~+85℃` as printed on the records read 2026-11-01 (it is in each row's `notes`, and the frequency figures of the rows are the datasheets' stability over that same range; the listing does not say which temperature it is). The other rows state none. The rows read from a datasheet each have a `temp_min, temp_max:` entry in `source` with the figure in Celsius, the document, its revision or date, the page and the table, and a sentence in `notes` that says which temperature the document means (`ambient`, or the `operating temperature` of a document that does not say ambient, junction or product temperature). The figure is the document's own and not a class's: a manufacturer's datasheet that names the series and whose part-number code covers the row. Filled: all 61 capacitors (39 Samsung CL rows from the symbol table of Samsung's MLCC catalog, page 5, and the three part specification sheets that say the same; 20 Fenghua rows from its product specification A0001, page 3/27; the Yageo CC0603 X7R from the Class 2 X7R datasheet, page 14; the Murata GRM158R61A226ME15 from its own specification, page 1); 216 of the 219 resistors (197 UNI-ROYAL 0402 and 0603 from the Ratings table, page 5, -55 to 155 C; 12 KOA RK73H2A from the ratings table; GiantOhm GR0402, Ever Ohms CR0402, Yageo RC0402, Stackpole RMCF0402 and UNI-ROYAL CQ02, one to three rows each); the 3 Murata ferrite beads (-55 to 125 C, operating temperature); 6 RUILON polymer fuses (-40 to 85 C, ambient operating conditions, page 1); the 8 single-row headers and sockets (-40 to 105 C: Hanxia's approval sheet says ambient, the JXTCONN drawings say operation temperature) and the 3 two-row headers (-40 to 105 C, `Operation Temperature` of the JXTCONN A254M01-0BxP51-H25A60 drawing for the 2x3 and 2x5 and of Hanxia's HX PZ2.54-2x10P ZZ drawing for the 2x10, read 2026-11-16); the 3 Murata LQH32PN inductors (-40 to 85 C ambient, self-heating not included). **A JUNCTION range is the part's range** for 27 of the semiconductor rows (ADR 0099, the owner's decision of 2026-11-10): the datasheets of the Schottky diodes, the TVS diodes, the Zener diodes, the AO3400A and the AO3401A give a junction range (`TJ`, or `TJ, TSTG` in one figure for junction and storage) and no ambient one, so the row's figure is that junction operating range, each row's `notes` say so (`junction`), and the environment check judges the part by it: a junction range that covers the environment is a pass. The part's own heating above the ambient is not computed, so a part that runs hot can be at a junction temperature above its figure while the air is inside it; that is the limit of the check, and the storage range is never used. The rows: SS14 (-55 to +150 C, MDD SS12 THRU SS1200 Rev:2025A5), SS34 (-55 to +125, MDD SS32 THRU SS3200 Rev:2024A5), SS210 (-55 to +150, MDD SS22 THRU SS2200 Rev:2024A4, the SS26 to SS2200 column), SS54 (-55 to +125, MDD SS52 THRU SS5200 Rev:2024A4, the SS52 to SS55 column), SS3H10-E3/9AT (-65 to +175, Vishay 88752 revision 13-Nov-2025), the 5 SMAJ and 4 SMBJ rows (-65 to +150, MDD Rev:2025A6 and Rev:2025A7), the 3 SMDJ rows of `tvs.csv` and `tvs_bidirectional.csv` (-65 to +150, Littelfuse revised 11/20/15), the 8 BZT52 rows (-55 to +150, Changjing Rev. - 2.1) and the AO3400A (-55 to +150, AOS Rev 3 Dec 2011), each on page 1. **12 LED rows state the operating temperature range of their datasheet** (`Operating Temperature Range`, `TOPR`, page 3: -40 to +85 C, and -30 to +85 C for the XL-1005UGC; the Lite-On LTST-C190KGKT Revision N, page 3, -30 to +85 C, and the LTST-C193TBKT-5A, page 2, -20 to +80 C), which does not say ambient or junction; the XL-1608 and XL-1005 datasheets that name their part (for the XL-1608UBC-04 and UGC-04 the name is in the image of the header, not in the text layer). **Read 2026-11-11:** the 5 more LEDs above, the two one-time fuses (the prosemi 1206HV-3A and the Walter 1206T3A63V both -55 to +150 C, operating temperature with the rating derated; the Walter sheet page 7, the prosemi sheet page 2, whose axis is the ambient temperature), the XC6206 (-40 to +85 C, `Operating Ambient Temperature`, ETR0305_004b page 3; the LCSC link is a web page that names the PDF, which was read), the 1N5819WS (-50 to +125 C, one `Operating and Storage Temperature Range` figure, page 1, not stated as junction or ambient), the VO SCR0402F38K3 (-55 to +155 C, IE-VO-V1.4 of 2021.07.12, the operating temperature range cell that spans the 0402 to 1206 rows) and the Hottech RI0402L24R0FT (-55 to +155 C, page 4, row RI0402). Left empty, with the reason: the B5819W SL (a junction maximum of 125 C and no minimum) and the 2N7002 (a junction maximum of 150 C and no minimum; the storage range is not used), the Chilisin MHCD322512 inductor (the rating table's page 53 of the file the link opens prints `Operating temperature range -40 to 125 C (Including self-temperature rise)`, an earlier note here said -55 C, which is the figure of another series of the same file, so it is not an ambient figure), the KT-0603R (its approval sheet, revision A.0 of 2018-12-06 and the same maker, prints `Topr -40 to +85 C` on page 3 but names the product only as `0603-0.6` red, not KT-0603R) and the KT-0603W (its sheet is another maker's approval sheet for a white 0603 LED), and the VO `0402 +/-1% 16R` C2906400 (the LCSC record links the same IE-VO-V1.4 sheet as C3016001, but its manufacturer number carries no SCR ordering code to tie it to the sheet). A row left empty stays offered and named.
- **`qualification` is a fixed column** (ADR 0099, provisional), the last one of a file that has it: `Aec` where the row's datasheet, or the maker's product page, says the ordering code is qualified to an AEC standard (AEC-Q100 for integrated circuits, Q101 for discrete semiconductors, Q200 for passives: the row's `notes` say which one the document states), `None` where the document says the ordering code is not the qualified one, and an empty cell where nothing says, which a board that requires `Qualification::Aec` offers and names. A cell is filled only from a document the engineer read; never from a series' name (`Automotive` in a title), a part's family or memory. The row's `source` has a `qualification:` entry with the document, its revision if it prints one, the page, the sentence and the day it was read. **Two rows state it, both read 2026-11-11:** `1206HV-3A` (`fuse.csv`) is `Aec`, as AEC-Q200: the prosemi 1206HV series datasheet (document P0F0510130943002A, no revision printed), page 1, Features, "AEC-Q200 Automotive Grade Certified". `SS3H10-E3/9AT` (`schottky.csv`) is `None`: Vishay document 88752, revision 13-Nov-2025, page 1, "Base P/N-E3 - RoHS-compliant, commercial grade" against "Base P/NHE3_X - RoHS-compliant and AEC-Q101 qualified". Only `fuse.csv` and `schottky.csv` have the column; every other row states nothing. The datasheets of the other rows were not read for a qualification (the UNI-ROYAL CQ resistors are called Automotive in their series name, and no row's notes say the datasheet states AEC), so their cells stay empty.
- **`height` is a fixed column** (ADR 0094): how tall the part's body stands above the face of the board, one length such as `2.62mm`, **the greatest the manufacturer's document allows** (the maximum of its outline table, or the nominal plus the tolerance the drawing prints; when a drawing prints inches and millimetres that differ by rounding, the larger). The part's `.height` is it when a design states none, so a board with a height limit checks the part instead of reporting it `unchecked`. A cell is filled only from a document the engineer read (the outline drawing or table, not a typical value, not a package's name), and the row's `source` has a `height:` entry with the document, its revision or version, and the page and table or drawing. An empty cell means unknown; never write 0 or an estimate. A pin header's height is the whole height above the board with the longer pin up.
- **`manufacturer` is an optional fixed column** (ADR 0143): who makes the part, as its datasheet spells it. With the `mpn` it is the row's identity: two rows of one `mpn` from two manufacturers are two parts, the same manufacturer and `mpn` twice is refused naming both places, and a row with an empty cell is its `mpn` whoever makes it, so it is the same part as any row of that `mpn`. **No standard file has the column yet.** It is filled only from the datasheet (or the maker's product page) a person read, with the document in the row's `source`, and never fetched for the existing rows from a supplier: `catalog refresh` and `catalog add` read an unofficial endpoint whose terms of use are unread (ADR 0039). `netsmith catalog add` writes the manufacturer of the LCSC record it already reads, as LCSC spells it (`muRata`, `MDD(Microdiode Semiconductor)`), into a file that has the column, and says so in the `source`; check the spelling against the datasheet. A row that names a manufacturer must have an `mpn`.
- **The offers files, `data/offers/jlcpcb.csv` and `data/offers/lcsc.csv`** (ADR 0143, stage 2), hold one offer of each row with an `lcsc` from each supplier: the part's `manufacturer` and `mpn`, the `sku` (the row's `lcsc`, the LCSC number JLCPCB assembles the part by and LCSC sells it by), the `class` (the row's `library` in `jlcpcb.csv`, empty in `lcsc.csv`), the `source` (the first part of the row's `source`, the record of JLCPCB and LCSC the numbers were read from, with its day), the row's `checked`, and `notes` that name the row's file, whose `source` and `notes` hold the rest of the evidence. Their format is in `crates/netsmith-solve/src/offers.rs` and the guide (_Offers files_, chapter 12). **The rows still hold the numbers:** the offers are made from them, and nothing was fetched from a supplier to make them. After adding a row or changing its `lcsc`, `library` or `checked`, run `cargo run -p netsmith-solve --example offers_from_catalogs`, which writes both files again from the catalogs, and commit them with the row: the test `offers::the_standard_offers_are_the_standard_rows_columns` (`cargo test -p netsmith-solve --test main offers::`) fails while a row and its offers differ.
- **Every row is offered.** To stop offering a part, move its row to `considered.csv` with the reason in its `not_offered` column.
- **A row needs a `source`**, the evidence described next. The loader refuses a row with an `lcsc` or `mpn` and no source. `netsmith catalog add --lcsc C123 --to <file>` starts a row from LCSC's record (#454): it fills `lcsc`, `mpn`, `package` and a `source` naming the record and the day, and leaves the datasheet's cells and `library` empty for a person to fill, with their source.
- **Cells use the language's syntax**: `10kohm +/- 1%`, `3.3V +/- 5%`, `1.8V..2.4V`, `0.68V`, and bare text for `package` and `color`. `name` is what messages call the row and `label` is the schematic's value field.
- **`effective_capacitance`** is `derate capacitance by bias: <volts>:<fraction> ...`, the capacitor's DC-bias curve (see below). Nothing after the colon means no curve is published.
- A project adds its own parts in its own repository, not here: `catalogs = [...]` in its `netsmith.toml`.
- **Curve files** (`catalog/curves/<catalog>/<row>.csv`, issue #1260) give a column of one row as points over the part's current and the board's temperature, such as a diode's forward voltage or a linear regulator's dropout (`curves/ldo/<row>.csv` over `output_current`, issue #1259); the row keeps its single figure. Their format is in `crates/netsmith-solve/src/curve.rs` and the guide (_Curve files_, chapter 12). **No row has one yet.** The `ldo` row of the XC6206P332 (C5446) has none (issue #1301): its datasheet (ETR0305_004b, p.8, (4) Dropout Voltage vs. Output Current) draws the dropout down to 0 A only for the XC6206P122, P302 and P502, as typical curves, and its table gives the 3.3 V part's maximum at 30 mA and 100 mA alone, so a curve for it would be drawn from its family or start at 30 mA. Of the standard buck ICs none states `high_side_resistance`: the LMR16006Y and the LT8641 stop short of 100 % duty cycle, and the RT8059 and the TPS54202, which reach it, give their high-side on-resistance as a typical figure only (their parts' doc comments say where). A curve file is added only with its source, as a row is: the row's `source` gets a `curve:` entry that names the datasheet, its revision, the figure (`Typical Forward Characteristics`), whether the curve is typical or a bound, how the points were read (from numbers the maker gives, or off the drawn line by pixel position against the gridlines, as the capacitor curves below were) and what margin was added. A curve that is a typical figure is said to be typical in the row's `notes`, since a check that reads it is then a typical check. Never draw a curve from a part's family, a SPICE model of another part or memory.

## Evidence rules

Every row has a `source` column (`considered.csv` calls it `evidence`) with, in this order:

- `JLCPCB and LCSC part records, read <date>`: the row was written from the JLCPCB and the LCSC record of that exact number, read on that day (2026-11-01, or 2026-11-02 for the pin headers; the date says when the identity was read and promises nothing about price or stock). Both records agree on the manufacturer's number, the package and the value.
- `datasheet:<url>`: the manufacturer's datasheet, where the model uses a number from it. Regulator and LED pinouts, dropout, current and capacitor requirements come from the manufacturer datasheets (links in the `source` column), read as PDF text and, for the XC6206, as page images.
- `bias-curve:` and its test conditions, for a capacitor with a DC-bias curve (below).
- `esr:` and the cell's figure, for a capacitor row that states an ESR (below): the document, the page, the table or graph and the point it was read at.
- `curve:`, for a row with a curve file (above): the document, the figure and how its points were read.
- `life:`, for a capacitor row that states `capacitance_at_end_of_life` or `esr_growth` (issue #1256): the maker's document, the page and the table of its endurance (life) test, with its hours, temperature and voltage, and the limits it prints ("capacitance change within -30 % of the initial value" is `0.7`, "ESR not more than 200 % of the initial specified value" is `2`). **No standard row states either yet**: none has a recorded source, so the solver's tests and the guide use invented rows. An ESR over temperature is a curve file of the `esr` column with the axis `temperature` (above).

The row for C5446 (XC6206) has no date: its source is the two records and the datasheet.

No part number came from memory. Part names were used only as search keywords, and a row exists only if the records returned that exact C number with the expected value and package.

**Recommendation: C5446 (XC6206P332MR-G).** It is the only 3-pin, Basic, ceramic-capable choice.

- **Pin-to-pad map**, KiCad `Package_TO_SOT_SMD:SOT-23`: pad 1 = GND (VSS), pad 2 = VOUT, pad 3 = VIN. Datasheet SOT-23 top view: pin 3 is the lone pin on one side, pins 1 and 2 are on the other.
- **AMS1117-3.3 (C6186)** is the wrong part for the example. The datasheet asks for a 22 uF tantalum output cap, and a 4.7 uF ceramic is not a supported configuration.
- **Power dissipation, `max_power`.** Page 3 of the datasheet (absolute maximum ratings, Ta=25 C) lists Pd for SOT-23 as 250 mW (SOT-89 500, USP-6B 100, TO-92 300) and notes `IOUT = Pd / (VIN - VOUT)`. Read on 2026-11-01 from the datasheet PDF that the JLCPCB record of C5446 links (the same file as the `datasheet:` URL in the CSV row). netsmith uses 0.25 W for the XC6206P332MR-G, not derated for a hotter board.
- **Limit 1: current.** The XC6206 SOT-23 package is limited to 250 mW. With 5.25 V in and 3.3 V out that is about 128 mA. The example states a 0 to 50 mA load on the output, and the solver checks that against the 100 mA modelled limit and the 250 mW.
- **Limit 2: output tolerance.** The datasheet gives 3.3 V +/-2% (3.234..3.366 V) only at 25 C, Vin 4.3 V, Iout 30 mA. The datasheet adds typ +100 ppm/C, load regulation of 60 mV max over 1..100 mA, and line regulation. The worst case over temperature and load is therefore wider than +/-2%. The example's `3.3V +/- 2%` constraint cannot be guaranteed by this part. Either relax it to about +/-4%, or use ME6211C33M5G-N (+/-1%), which is Extended and 5-pin.
- **Limit 3: 4.7 uF output cap.** The datasheet only states 1 uF ceramic for CL and gives no maximum. Larger ceramic is normal practice but not specified. A 4.7 uF 10 V 0402 X5R loses a large share of its capacitance at 3.3 V DC bias; see "Capacitor DC-bias curves" below for the numbers.
- **Layout guidelines (`std/layouts.nsm`, issue #1032): not possible for C5446.** A row carries a `layout "MPN" for Generic { }` block there only when its datasheet has a layout section. The XC6206 datasheet (Torex ETR0305_004b, the 17 pages read as text and as page images on 2026-11-16) has none: it gives no placement advice for the input and output capacitors or for the pins, and the only land pattern on its pages is the USP-6B's "Reference Pattern Layout" and "Metal Mask Design" (page 14, a package this catalog does not hold), with the page 2 note that the USP-6B dissipation pad "should be connected to the pin number 4 (VIN)". The SOT-23 has no land pattern in it, only the package drawing of page 13. So the row has no block, and a board that picks it has no datasheet guideline. A row added to `ldo.csv` is read the same way: its datasheet's layout section, or a line here saying why there is none.
- **5-pin alternatives (EN, NC).** Tie EN/CE (pin 3) to VIN. Both ME6211 and AP2112K are active-high with a 1.0 to 1.5 V minimum, and VIN is 5 V. Leave NC (pin 4) unconnected, or give it a no-connect net.

### Capacitor DC-bias curves

The `effective_capacitance` cell of `catalog/capacitor.csv` gives, for each capacitor that netsmith can pick, the fraction of its marked capacitance that is left at each DC voltage across it. The cell holds the curve as `volts:fraction` pairs from 0 V to the rated voltage. Where the curve is, the test conditions (`measured`) and the `margin` are in the row's `source` cell after `bias-curve:`, and its description is in `notes` after `Bias curve:`.

- **36 of the 61 capacitors have a curve, 35 Samsung and one Yageo.** `bias-curve: samsung-componentcenter:` rows come from Samsung's own Component Library, `https://weblib.samsungsem.com/mlcc/mlcc-ec-data-sheet.do?partNumber=<MPN without its last letter>`. The page embeds the "DC Bias" series as numbers (`datasheetData`, graph type `DCBias`, 25 C), from 0 V to the rated voltage. The last letter of the MPN is the packaging code and the tool leaves it off (`CL05A105KA5NQN` for C52923). Re-check one with `curl -sL 'https://weblib.samsungsem.com/mlcc/mlcc-ec-data-sheet.do?partNumber=CL05A105KA5NQN'` and read the `DCBias` block; the first Y value is the change in percent at 0 V and the X values are volts.
- **C23733 (CL05A475MP5NRNC) uses Samsung's characteristics sheet instead**, `https://media.digikey.com/pdf/Data%20Sheets/Samsung%20PDFs/CL05A475MP5NRNC_Char.pdf`, graph 3 (1 kHz, 0.5 Vrms). Its curve is deeper than the Component Library's 1 Vrms series for the same MPN (about -70% against -57% at 4 V, -90% against -85% at 10 V), and the lower one is the safe one. I took the points off the graph by pixel position against the gridlines (reading error at most 1 point). The same sheets for C47339 (CL05A474KP5NNNC) and C15525 (CL05A106MQ5NUNC) agree with the Component Library to within a point or two, and were not used further.
- **Murata C3845593 (22 uF 10 V) has no curve.** The datasheet LCSC links for it (`datasheet.lcsc.com/datasheet/pdf/8d242c3da788daca84b3abba710d6196.pdf`) is Murata's generic reliability text and has no per-part curve, and Murata's product page (`pim.murata.com`) returns no data without a browser. SimSurfing was read on 2026-11-16 (`https://ds.murata.com/simsurfing/mlcc.html`): the page opens behind a software licence agreement that forbids reverse engineering and disclosing the software to a third party without Murata's written consent, and the part data it loads is a zip of one CSV of per-part parameters (`https://ds.murata.com/simsurfing_data/data/mlcc.zip`, columns such as `A1`, `B1`, `F1`), not a curve. I did not accept the agreement for the owner and did not turn those parameters into a curve with the page's own formula. So the part is in the catalog, and the solver refuses it whenever a design constrains the effective capacitance (ADR 0013); a design that names only its marked `.capacitance` may use it.
- **Three 100 V X7R parts, added 2026-11-07, have a Component Library curve although they are class II parts of 1 uF or more** (the rule of the paragraph below leaves out the ones of 2.2 uF and more with a curve at 1 Vrms): C55151 (CL32B225KCJSNN, 2.2 uF, 1210), C170101 (CL31B225KCHSNN, 2.2 uF, 1206) and C13832 (CL31B105KCHNNN, 1 uF, 1206). Issue 179 asked for them with the Library's curve, a design with a 100 V rail needs one, and no other series for them could be fetched (the characteristics sheets at `media.digikey.com/.../<MPN>_Char.pdf` answer with a web page). The series is `dsDcSign` 1.0 (1 Vrms) at 1 kHz and 25 C, and the curves were made as below. They are deep: 0.97 to 0.99 left at 5 V and 0.14 to 0.17 at the rated 100 V, and a design that needs the capacitance at its rail has to say so (`effective_capacitance`). A test (`a_capacitor_without_a_curve_is_one_of_the_recorded_cases`) pins this rule.
- **What the curves say**, as the fraction left, as in the cell (so with the margin taken off, before the +/-10% or +/-20% tolerance), at 3.465 V and 5.25 V, the top of the regulator example's two rails: C52923 0.70 and 0.52; C1525 0.95 and 0.89; C16772 0.92 and 0.83; C15195 0.99 and 0.98; C47339 0.62 and 0.44; C315248 0.35 and 0.22; C23733 0.32 and 0.19; C15525 0.35 and 0.21; C16780 0.43 and 0.28.
- **How the curves are made.** Each curve is the source series sampled at 20 equal steps from 0 V to the rated voltage, each fraction rounded down to 0.001, then lowered by `margin` (0.01 for the Component Library rows, covering the straight line between samples, which was at most 0.7 points above the source; 0.02 for the C23733 graph, adding its reading error). A fraction above 1 (100 nF X7R rises 0.2% at 1 V) is held at 1.
- **What is not covered.** A curve is the typical value at 25 C, 1 kHz and the AC level in `measured`; Samsung says its data are typical, for design reference. The effective capacitance is the marked value with its tolerance times the fraction on this curve (the tolerance of the part is in its `capacitance` cell). **Temperature is not modelled.** Samsung's Component Library pages carry a typical temperature curve (`TCC`) for each part and the characteristics sheet of C23733 draws it, but no page read states the X5R/X7R class limit as a number for these parts, and one from memory is not recorded here. Ageing (class II capacitors lose capacitance over time), the AC level in use and the manufacturer's tolerance on the curve are not modelled either. No datasheet or standard was found that bounds a whole class of capacitors, so there is no class-level fallback: a part without a curve has none.

### Capacitor ESR (`esr` column, issue #420)

The `esr` column of `catalog/capacitor.csv` (optional, ADR 0078) is the equivalent series resistance of one capacitor: one figure in ohms at 500 kHz, never an estimate. A row states it only where its maker's document or the maker's own tool prints or draws it for that exact part; the `source` cell then has an `esr:` entry that begins with the cell's figure and names the document, its page, the table or graph and the point (frequency, and DC bias or its absence), and the `notes` cell says what was done to the reading (`ESR: ...`) and whether the figure is typical or a maximum. A figure read off a drawn curve is read by pixel position against the gridlines of the rendered page and rounded up to a whole mohm; a figure from numbers the maker gives is rounded up to two figures. `Buck` reads the picked row's figure as its `.output_esr` when a board states none (`docs/language/28-standard-parts.md`).

## Impedance calculator results (`impedance_calculator.csv`, issue #1007)

`impedance_calculator.csv` has the track widths that JLCPCB's own impedance calculator, https://jlcpcb.com/pcb-impedance-calculator, gave on 2026-11-16 for a target impedance, so that the calculator of `netsmith_pcb::impedance` is checked against the fabricator's (`crates/netsmith-fabricate/tests/impedance_reference.rs`). Each row was read from the page as a person reads it (a headless browser set the form, pressed Calculate and read the Trace Width of the stack-up tab named in `build`), with the page's defaults except as listed: board type Rigid, 1.6 mm, inner copper 0.5 oz, outer copper 1 oz, unit mil, impedance tolerance 0.5 %, type "Single Ended (Non coplanar)" or "Differential Pair (Non coplanar)". The columns: `build` (the page's stack-up tab, the "Standard" one for four layers), `type`, `impedance_ohm` (the target), `layer` (`L1` is the front), `top_ref` and `bottom_ref` (the signal layer's reference layers; the front's top reference is `/`), `spacing_mil` (the conductor spacing of a pair, edge to edge) and `width_mil` (the Trace Width the calculator gave). The page's tables of its stack-ups are the build-ups `std/mfg/jlcpcb.nsm` states (7628, 8.28 mil = 0.2104 mm; 3313, 3.91 mil = 0.0994 mm; the core 41.93 mil = 1.065 mm), read in the same sitting.

- The calculator states no formula. Its user guide lists the parameters it uses ("Calculation Parameters Used", last updated 2026-11-10): outer copper 1.6 mil, the soldermask 1.2 mil above the substrate, 0.6 mil above the trace, 1.2 mil between traces, its permittivity 3.8, and a trace whose top is 0.7 mil narrower than its base. The widths in the file are the base widths. The page does not say how it models a pair or the mask.
- Not recorded: a differential pair on the inner layers of the six-layer build-up (the form did not take the inputs in the runs made), coplanar types, other targets and spacings, and any build-up but the two named. These are not checked. A row is one reading of one target: eight rows are a check that the figures are in the calculator's neighbourhood (the test's limits are 5 % for a single track and 8 % for a pair, from the 4 % and 6 % the rows show), and not a proof that they agree.
- The figures are the calculator's on the day. If it changes, the test says by how much this crate then differs; a row is replaced by reading the page again, with the date here.

## What was not verified

- The jlcpcb.com HTML part pages were not read; the data came from the JLCPCB part records.
- C22369487 (23.7k 0402) appears in JLCPCB's records but LCSC has no record of it, so it is left out.
- Search coverage: JLCPCB's search returns a limited number of results for a keyword. "No Basic 270R/300R 0402" is based on scans of all returned rows for "0402 270Ω" and "0402 300Ω". The Basic LDO list came from keyword scans, so it is not guaranteed complete.
- The LCSC-hosted datasheet URLs in the `source` cells are canonical but block scripted download. The same PDFs were read from the file link of the JLCPCB record and their text extracted with `pdftotext`.
- Price and stock are not shipped (see the top of this file), so nothing here says that a part can be bought today.
- JLCPCB Extended parts normally add a one-time loading fee per unique part unless flagged Preferred. This was not checked on the order page. Preferred rows: C25102, C47339.

## Refreshing the rows

`netsmith catalog refresh` repeats **the LCSC cross-check only** for each row; JLCPCB data is not fetched (ADR 0039, decisions of 2026-11-02). It compares LCSC's manufacturer's number and package with the row's and, for a row that agrees (`VERIFIED`), writes the day in the `checked` column (`--dry-run` shows the diff, `--lcsc C5446` does one row). **It never writes `price`, `stock`, `price_breaks`, `library` or `date`.** A row whose LCSC record has another `mpn` or package than the row is a CONFLICT, and a part LCSC no longer lists is MISSING; both are left as they were. A new row's `checked` is empty until a refresh verifies it. LCSC's terms of use for the record the command asks for have not been read; a person must read them before the command is advertised.

A project that keeps its own prices and stock in its own catalog files (`price`, `stock`, `date`, ADR 0022) gets them in its bill of materials as the last resort, after a supply provider's answer, with the age of each `date` and a stale mark after 90 days; a standard row has none of them, so its line says its price and stock are unknown unless a provider has the part, and `netsmith catalog age` counts it as unknown.

## Re-checking one row

Look the number up on lcsc.com for the manufacturer's number and package, and on JLCPCB's parts page (jlcpcb.com/parts) for the library type, price and stock. A person does this by hand; nothing in netsmith reads JLCPCB's price, stock or library. Official APIs (JLCAPI, the LCSC API) need an account and are future work.

## How netsmith uses these files

`Catalogs::jlcpcb()` in `netsmith-solve` embeds every `catalog/*.csv` (`build.rs` lists the directory, so a new file needs no Rust) and a part that lists `catalog resistor { ... }` reads `resistor.csv` against its columns when the solver picks. `src/jlcpcb.rs` is only the loader. Each file is ordered Basic first, then by the prices read on a past date (not shipped, so that part of the order cannot be re-checked), then by ascending value, so the solver takes the cheapest Basic part that works. A test checks that every row has its evidence and no price, stock or date, that Basic rows come before Extended ones, that every curve names its source and ends at the rated voltage, and that nothing in `considered.csv` is offered.

The modelling choices are recorded here, and for the LEDs and the regulator in the rows' `notes`: resistors are 0402 +/-1% without the 0 ohm link (a jumper has no tolerance and a zero would let any current through); capacitors carry the tolerance and rated voltage from the supplier's record, their DC-bias curve as `effective_capacitance`, and `capacitance` as the marked value; the 1206 100 uF C15008 stays in `considered.csv` (when it was looked at KiCad had no 1206 capacitor footprint here; the std has one since 2026-11-07 for the 100 V parts, and the 100 uF part was not re-read); the LEDs' forward-voltage ranges are the datasheet minimum to maximum at the test current, and the Lite-On yellow-green C125094 is the "GREEN" LED; the XC6206 is +/-5% output (the datasheet's +/-2% holds only at 25 C), 0.68 V dropout, 0.1 A and 0.25 W. With these catalogs `examples/led.nsm` picks the Basic 0603 390 ohm C23151: the 330 ohm 0402 C25104 would carry up to the 15 mA of the window through up to 5.9 V, 88 mW, over its 62.5 mW (the 300 ohm C25102 is Extended and not needed once the window is 5..15 mA).
