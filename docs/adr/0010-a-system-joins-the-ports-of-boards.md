# A system joins the ports of boards

A design of several PCBs needs a way to join them, so a new top-level definition, `system`, holds boards and says which of their ports meet: `system Demo { .main: MainBoard  .io: IoBoard  .main.output ~ .io.input }`. A system holds nothing but boards (a part, a value or a pin in one is an error) and a board is placed only in a system. The same board may be placed twice; each is its own member with its own values.

A port is an interface that a board declares directly (`.output: Rail`). There is no `port` keyword, because the board already says what its interface is, and ADR 0004 already decides what a user of a board can reach: its interfaces and declared values, never the parts and modules inside. So `.main.output` is reachable, `.main.stage.vout` and `.main.r1` are not, and the error says that a system reaches only the ports a board declares directly. A system narrows a board the way a board narrows a module: through the board's ports and declared values (`.main.output.voltage &= 3.3V +/- 5%`), and no other way.

`~` in a system joins two ports of the same kind on different boards. It equates their values, as `~` does between rails on a board, and nothing else: it does not put their pins on a net. Only a board names nets (ADR 0005), so a system may not (`.net &=` is refused), and a net never crosses boards; two boards may each have a `GND` and a `3V3` and they are different nets. A system does not model connectors or pinout. Each board has its own header wired to its own port, and the join says that the two meet; nothing checks that the two headers mate pin for pin.

Currents are balanced at the join. A group of joined ports is one `Balance` in the system's scope. Each port is written as its board writes it (the current the outside draws through it), so the ports are mirror statements of one flow and count as they are: a board's `.output` at +X and the other board's `.input` at -Y are the same flow and add up to zero. When one port's current is unknown it is the negative of the rest, as on a net. When all are known, the sums must be able to reach zero, and a port whose current is never negative is a supply whose range is how much its board is built to give, so what the other ports draw must lie within it. The other direction is not checked: a board that takes 5 to 20 mA from an output written `0mA..50mA` is within it, and the 50 mA is not a promise that 50 mA flows. The existing balance on a net, which demands both directions, is right for a board where the rails behind the port are derived from it, and wrong for a stated envelope against an independently stated draw. The solver settles what a board draws from inside it first and lets a join fill in a port only when nothing inside can, because a join knows only what the others allow.

A board's own port that supplies the inside, with nothing inside to take that current that the checker knows of, is taken as stated and not reported. A chain of parts that draws from the port's net now counts (ADR 0014), so a board that draws through an LED and a resistor states nothing; what is left is a part that draws and is neither in such a chain nor holds a rail. A load with nothing to supply it is still reported.

The checker builds one model for the whole system, with each board as a member, and the solver solves it once. Propagation already carries values across a join and picking reads what propagation settled, so this reaches the fixed point that boards depending on each other's ports need without iterating board by board, and one bad join is reported once. Lowering reads one board at a time through a view of the model (`Model::scoped_to`) that has the board as its root, so each board lowers as it would alone: its parts numbered from one, its nets named from the board, its files named after the board definition. `netsmith build` writes `<out>/<System>/<member>/` for each board of a system and `fab` a package there; a board a system places is built only as that system's, a board no system places is built as before, and a file with only a board needs no wrapper. `view` lists the boards of a system as `System/member` in its board selector.

Limits. Connectors and pinouts between boards are not modelled here; ADR 0040 adds mating pin headers and sockets, which derives the joins of the ports the contacts carry. The system balance treats several supplying ports on one join as if each had to cover the whole demand alone. Modules as sheets of one board (hierarchical modules) are a separate step.
