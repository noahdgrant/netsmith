# The editor is a local web app served by the netsmith binary

Meets tests 1 (the committed bundle and the Node needed to change it are hard to take back out) and 3 (a hand-made text editor and a desktop shell were the obvious alternatives). The status line was `accepted` before the cut. The text before the cut is `git show 31d3394:docs/adr/0019-the-editor.md`. The server's routes, its guard and its jobs are the header of `crates/netsmith-editor/src/server.rs`; the types that cross to the page are `crates/netsmith-editor/src/api.rs`; the build of the page is the headers of `crates/netsmith-editor/build.rs` and `build_web.rs`.

**Decision.** `netsmith editor` is the front end of netsmith: a project tree, a source editor with the real compiler and solver messages inline, and views of the board the source describes (schematic, power tree, system, bill of materials, PCB), with buttons for the build and for `fab`. It replaces `netsmith view`, which showed the schematic and nothing else and is removed (ADR 0001: one way to look at a design). The language stays text (ADR 0003): the editor writes `.nsm` files and the files beside them that are its own (ADR 0032, ADR 0061), and never a second copy of the design.

**A web app, served locally.** The binary listens on `127.0.0.1` (port 8787 unless `--port`) and the user opens the address in a browser (on WSL, the Windows browser reaches it). Everything the page needs is embedded in the binary: no CDN, and no request leaves the machine at run time. The server refuses a Host that is not its own (a rebinding page) and an Origin that is not its own, and a request that changes anything must carry `X-Netsmith: 1`, which a page on another origin cannot send without a preflight the server never answers. It reads and writes only files that the project names.

**Rust and TypeScript.** The back end is `axum` on `tokio`, with JSON endpoints and one WebSocket. The front end is TypeScript with Preact, built by Vite, with CodeMirror 6 as the source editor; its source is `crates/netsmith-editor/web/`. The request and answer types are written once, in Rust, and `web/src/api.ts` is generated from them with `ts-rs` (a derive on the plain serde types; `specta` needs a registry to keep in step). The crate does not know the compiler: it holds the server, the types and the page, and a `Backend` trait that `netsmith` implements, because a crate the binary uses could not use the binary's library back. That also lets the server be tested with no compiler behind it and keeps `axum` out of every crate but one.

**The page is a committed bundle.** The built page is committed in `crates/netsmith-editor/web-dist` with a hash of its sources, so building netsmith from a checkout or a package needs no Node. A change to `web/` needs Node 20 or newer and `scripts/web-bundle update`, and `scripts/web-bundle` checks that the committed bundle is what the sources build to. A build that cannot make the page says why when `netsmith editor` starts.

**Rejected.** A small editor of our own (a `<textarea>` painted over by a `<pre>`): the editor is the product, and undo that survives a file switch, selections, search, a gutter that scrolls with the text, squiggles and bracket matching are work CodeMirror has done well. The grammar for `.nsm` is ours either way (`web/src/nsm.ts`). A desktop shell (Tauri) first: the page already talks only to a base URL, so a shell is a later wrapper and not a different design. Hand-copied API types: they drift. `netsmith view` kept beside the editor: two ways to look at a design.

**The cost.** Changing the page needs Node once, where the rest of netsmith needs only Rust. The committed bundle is a build product in the repository and must be updated with its sources. One user, one browser: the server has no accounts, and a second tab edits the same files. The views describe the whole project at the last check and are not incremental, so a project of hundreds of parts feels the solve. Verifying a change to the page means driving it in a real headless browser (`scripts/editor-verify`).

**Left open.** A desktop shell (Tauri) around the same page, later and not built. Refreshing price and stock online would be an opt-in `netsmith catalog refresh` that writes dated data into `data/jlcpcb/` (it exists: ADR 0039); the solver never needs the network, and the editor shows the dates it has. The editor completes names while typing (`web/src/source/complete.ts`), and `netsmith.toml` is shown and not edited. Moving a symbol, which this ADR first sketched with a `<stem>.layout.toml`, is ADR 0061.
