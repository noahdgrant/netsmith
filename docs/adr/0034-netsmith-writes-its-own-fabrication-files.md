# netsmith writes its own fabrication files

Meets tests 1 and 3: every board goes out in this package (hard to reverse), and `kicad-cli` as the writer is the obvious alternative. The owner reviewed it on 2026-11-04 and the text relied on for `accepted` is "The owner accepted the design on 2026-11-04" (the status line it had said "accepted in design, provisional until a package has been through JLCPCB's order preview"; the condition is kept below, and the owner can say `proposed` instead). The text before the cut is `git show 0eaf326:docs/adr/0034-netsmith-writes-its-own-fabrication-files.md`. What the writers do, the rules found by the cross-check and the limits are in the headers of `crates/netsmith-fab/src/lib.rs`, `plot.rs`, `fill.rs`, `artwork.rs` and `crosscheck.rs`; the user's view is `docs/LANGUAGE.md` ("Commands").

ADR 0021's direction says netsmith must not need KiCad installed, and a person with the `netsmith` binary alone must be able to make the files a board house takes. Until then `kicad-cli` plotted the Gerbers, drilled the Excellon files and wrote the position file.

**Decision.** `crates/netsmith-fab` writes all of them from the `.kicad_pcb` text: the Gerber (RS-274X, X2) for every copper, mask, paste, silkscreen and outline layer, the drill files, the placement file, and the fill of the pours, which a board with pours cannot be plotted without. The writers are the only way: no flag gives back KiCad's files, and `package` takes no KiCad. `kicad-cli` is an optional witness: `netsmith fab --cross-check` plots the same board with KiCad and compares, and fails on a difference. The design rules check is netsmith's own as well (ADR 0037). One reader of the board file (`artwork`) serves the Gerbers, the drill and the check, so a board ported from KiCad plots as well as one netsmith wrote, and what it cannot make it refuses with the pad, via or zone named.

**The cross-check compares bitmaps.** Three methods were weighed. Comparing Gerber text breaks on harmless differences (a macro or a region, an arc kept or cut, order). Comparing lists of flashes and draws after normalising needs a second parser that understands every aperture and macro, and the rasteriser written for the cross-check is that parser, after which it does not matter how a shape was written. The limits were measured: copper, mask, paste and outline 1% of pixels and 0.1% beyond 0.05 mm, a pour 0.5% beyond the tolerance (KiCad removes islands and spokes that no pad reaches and netsmith leaves them), silkscreen 5% beyond 0.6 mm because the font is ours. Drill files and the placement file agree exactly. A fault of one KiCad release is allowed for in a copy of netsmith's files and never in the files written; each such difference has an entry with its evidence, and a new one still fails the check.

**Rejected.** Keeping `kicad-cli` as the writer: it needs KiCad on the machine, which the direction of ADR 0021 rules out. KiCad's stroke font: its glyph data is not ours to copy, so the silkscreen uses a font of our own (about 100 glyphs), and a character it lacks is drawn as a box and named in `fab-notes.txt`, never dropped.

**The cost.** The writers must be right, and the cross-check is the evidence, not proof. Where netsmith and KiCad differ by design the silkscreen letters differ and a pour keeps dead copper. Not done: hatched fills, zone priorities, per-zone island settings, text boxes, curves and images (named in the notes), a `padstack` pad, blind and buried vias. The pour is written in clear polarity inside a copper file, which CAD tools write for planes and KiCad does not.

**Left open, and the owner's.** JLCPCB has not been given these files, and every package JLCPCB accepted before was KiCad's. The condition for this ADR to stop being provisional: one real package goes through JLCPCB's order preview and its own design check (issue #12). The person who does it looks at the planes and at the silkscreen, and writes the result here: the board, the date, what the preview showed and any file JLCPCB refused or changed. Only the owner can do this, since it needs an order account. Until that entry exists nothing here claims that JLCPCB accepts these files. Result: none yet. No other Gerber viewer was available to script, so the only independent readers are KiCad's plot and the rasteriser, which reads KiCad's own files as well.
