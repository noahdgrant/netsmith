# Track width against current

Builds on ADR 0020 (net classes: `Rail.min_track`), ADR 0007, ADR 0014 and ADR 0027 (the solved currents) and ADR 0030 (manufacturing limits block `fab`, guidelines warn).

## Problem

A rail's `.min_track` sets the width of its nets, and the solver knows the worst-case current the rail draws. Nothing compared them: a 2 A rail drawn at the process's 0.1 mm built and went to the board house, and the track would have been a fuse. A rail that states no `.min_track` is drawn at the process's least, so the commonest mistake is the silent default.

## Decision

**The check.** After the currents are solved, lowering checks each net with at least two terminals. The net's current is the largest magnitude, taking the top of each range, of the things on it: the rails (any interface with a `current` that draws) with a pin on it, and the parts with a `current` whose `bridge` ends on it. The second is how the nets inside a series chain, which belong to no rail, take the chain's current (ADR 0014 equates neighbouring parts of a chain). The net's track width is the widest `.min_track` bottom of the rails on it, and never less than the process's least track; a net no rail states a width for is drawn at the process's least, so a 2 A rail with no `.min_track` is a finding. That is the width the router uses (`Board::track_width`).

The width needed is IPC-2221's formula solved for the width: `I = k * dT^0.44 * A^0.725`, `I` in amperes, `dT` in kelvin, `A` in square mils (width times copper thickness), `k` = 0.048 for a track on an outer layer and 0.024 on an inner layer. The router draws on the outer layers only, so the check uses 0.048 and the outer copper, `stackup.copper_weight` ounces of 0.035 mm (the same unit conversion the board file writer uses). The inner-layer constant is in the code (`Layer::Internal`) and is tested, for the day tracks go on inner layers; nothing uses it now. The relation is nonlinear in the current and the width, so it is a dedicated check and not a relation of the solver. A net that is an inner plane or an outer pour is not checked: it is an area, not a track.

A finding names the net, the current range and what carries it, the track width and where it comes from (a rail's `.min_track`, or the process's least because no rail states one), the copper weight and thickness, the rise and whether it is the default, the current that width carries, and the width needed rounded up to 0.01 mm so that writing the number the message asks for passes.

**The temperature rise.** `.process.max_temperature_rise`, a new `Temperature` field (a new built-in quantity type, kelvin) of `TwoLayer` and `FourLayer`, stated by neither. It is an upper bound like `via_in_pad`: the tool uses the top of the range (`&= 20K`). When the board states none, the check uses **10 K**. That is a stated default of netsmith's, chosen because it is a conservative, commonly used design figure; it is not a number a fabricator publishes, so the process does not carry it, the message says "(the default)", and `std/mfg/jlcpcb.nsm` says so where the field is declared. Copper weight needed no new field: `.stackup.copper_weight` was already in both processes.

**Guidelines warn, with a mechanism.** ADR 0030 accepted that manufacturing-rule violations block `fab` and guideline violations warn, with a key in `netsmith.toml` and a flag for one run. IPC-2221 is a design guide, not a limit of JLCPCB, so it is a guideline. This ADR builds the general mechanism: `[project] guidelines = "warn" | "error"` (default `"warn"`), and `--strict` on `build` and `fab` for one run. A check produces a `Guideline` (rule, message, the instance it is about) and the pipeline decides. Under `"warn"` the finding is a `warning:` line from `build`, a line in `fab-notes.txt`, and a warning in the editor's problems panel at the rail or part (through the existing diagnostics: `Built.guidelines`, no editor change beyond one function); under `"error"` the build stops with one error per finding at the same line. The policy travels in `Catalogs` (`with_strict_guidelines`), as the default assembly of ADR 0028 does, so every command that builds applies it. The editor takes the manifest key and has no flag. The later layout constraints of ADR 0030 (datasheet "put the capacitor next to pin 3") are the next guidelines and use the same mechanism.

## Why IPC-2221 and not IPC-2152

IPC-2221 is the formula in every track width calculator and is easy to state and to test by hand. It is a conservative guide: its curves were fitted to old measurements of tracks on thin boards and ignore the board's thickness, the planes near the track and the copper around it. IPC-2152 is more accurate (it accounts for those) and can allow a narrower track, but it is a family of charts and corrections, not one formula. We implement IPC-2221 only. A track that passes is not thereby safe at the stated rise, and one that fails may be fine; the finding is a prompt to decide, which is why it warns.

## Limits

- The current of a net is the largest single current on it in the original decision; the amendment of 2026-11-04 below replaces that with the sum. Where a current is not known, amendment 3 sizes the net for the sum of the known ones.
- A net is checked at one width, the net's. The router may draw shorter runs narrower where there is no room (a neck-down between pads, a stub at a pad's width), and the pad's own copper carries the last millimetres. Vias are not checked.
- The router's masks reach as far as the width of the track needs: a track wider than a via once reached further than the masks looked, which put 0.6 and 0.9 mm rails too close to other copper (shorts included). Every line the router returns has also been measured as drawn, against the other nets' pads, tracks, vias, holes and the board edge; a track nearer than the rules allow is drawn at the process's least instead, and a line that still is too near is left unrouted.
- Nets that are planes or pours are not checked; a pour's real width at a bottleneck is not measured.
- No ambient temperature, no duty cycle: the worst-case current is taken as continuous.
- Inner tracks are not drawn by the router, so the inner-layer constant is unused.

## Amendment: the router sizes every net (issue #4, PROVISIONAL)

The owner's direction on issue #4 was: there are standards for track width by current, the router should work the current out of the schematic, and a user who has to state a width has found a failure of the router. So no new syntax was added, and the check above stopped being the only use of the formula.

**What changed.** After the currents are solved, lowering gives each net with at least two terminals the width IPC-2221 needs for the largest current on it, taking the top of the range and rounding up to 0.01 mm, whenever (a) no rail on the net states a `.min_track`, (b) every carrier on it has a known current, and (c) the width is more than the process's least. That width is put in `Features::net_widths`, as if a rail had stated it, so the router, the board file's net classes and the check all see it. The nets that matter are the ones no rail touches: the node between a fuse and a diode in a `~>` chain takes the chain's current through the `bridge` of the parts on it (ADR 0014), and gets 0.79 mm for 2 A. Nets with a rail get the same when the rail states no `.min_track`; before, they were drawn at the process's least and warned about.

**An explicit `.min_track` stays an override.** A net where a rail states `.min_track` is drawn at that width, and the check warns if IPC-2221 needs more, exactly as above. The statement is the user's decision and is not raised silently. The warning therefore no longer fires on a net the router sized.

**A current that is not known.** A carrier is a rail that draws or a part that passes a current. If any carrier on the net has no worked-out current (the solver leaves the currents of a net with two or more unknowns unsolved, issue #18), the net is not sized: the other carriers' currents are only a lower bound, and a guess is as likely too narrow as too wide. It keeps its old behaviour (the rail's `.min_track`, else the process's least; the check warns if the known currents already need more), and `build` prints a note, `the current of rail `r`, part `p` is not known (...), so the tracks of net `N` are not sized from their current and are the process's least, 0.1 mm; ...`, naming the net and the carriers. `fab` writes it in `fab-notes.txt` too. A note and not a guideline: it does not change with `--strict`, because there is nothing for the person to correct in a finding the tool cannot make.

**The formula, its source and what was assumed.** `I = k * dT^0.44 * A^0.725`, from IPC-2221B section 6.2 "Conductor current carrying capacity" (the fit also in IPC-2221A; the chart is Figure 6-4). `I` in amperes, `dT` in kelvin above ambient, `A` in square mils (the width times the copper's thickness; 1 mil is 0.0254 mm); `k` = 0.048 for a track on an outer layer, 0.024 on an inner layer. The standard is paywalled and was not read. The formula, the constants and their units were taken from several agreeing derivations (Altium's IPC-2221 calculator page, the `pcb-toolkit` crate's `current.rs`, circuit.rocks and PCBCart; the last writes the area exponent as 0.75, which the others and the standard's curve fit do not). Hand-worked values are in `crates/netsmith-lower/tests/guidelines.rs`. Because the source was not the standard itself, the constants are PROVISIONAL until someone with the standard compares them. Also PROVISIONAL, and assumed and not from the standard: the copper is the process's `stackup.copper_weight` (1 oz, 0.035 mm, for JLCPCB's two-layer outer copper); the rise is `.process.max_temperature_rise` or, when none, 10 K; tracks are on outer layers (k = 0.048), as the router draws nothing inner; no ambient temperature or duty cycle.

**Left open.** (Closed by amendment 2 below: the sum and the regulator's input are now derived.) A router that necks down a run still draws it narrower where there is no room. Wide nets can make a tight board harder to route; no limit caps the width. The ranges of the IPC fit (small currents, rises, widths) are not checked: outside them the result is an extrapolation.

## Amendment 2: the current of a net is the sum, by Kirchhoff's current law (issue #4, PROVISIONAL)

Issue #4 was reopened with the owner's direction (2026-11-04): analyse the current in the system the way an EE does when designing the circuit. The first amendment took the largest single current found on a net. That is wrong wherever two things share a net: a ground that two rails return through carries both, and a regulator's input is not its output. This amendment replaces "largest single current" with a per-net current analysis. No syntax is added and the solver is not changed; what changes is how lowering (`guidelines.rs`, `plan_tracks`) reads the currents the solver already worked out.

**The sum.** The things that put a current into a net or take one out are the carriers: a rail (a load takes its `current` out of the net its `pos` is on and puts it back into the net its `neg` is on; a supply, whose current is negative, is the reverse) and a part that passes a current (it leaves the net of the first end of its `bridge` and enters the net of the second, so the nets inside a `~>` chain take the chain's current). Taking the top of each range, a net's current is the sum of what is taken out of it, with every load on at the same time. The sum of what is put into it is the same by Kirchhoff's current law when the balance is complete; the larger of the two is used, so that a pin the model leaves out (ADR 0027), or a supply stated as a budget wider than its loads (ADR 0038), makes the result larger and not smaller. A ground shared by a 2 A rail and a 1 A rail is a 3 A net, and each supply net carries its own current. The message names the sum, and its largest terms (up to four, then "and N more") when there is more than one: `net `GND` carries up to 3 A (the sum of the currents on it with every load on at once: rail `load_a` 2 A + rail `load_b` 1 A)`. The finding is placed at the largest term.

**Worst case, and where it is pessimistic.** All loads are on at the same time and each draws its largest current, so the sum is an upper bound. It is pessimistic in three ways, each a limit and none corrected: loads are not correlated (two that cannot draw together are both counted at their largest); no duty cycle or averaging; and a ground that the load of a regulator's output and the regulator's input both return through carries the sum of the two, because the supply of the regulator is a load on the input side and its output is a load on the output side. The load's return really goes to the regulator, and only the input's goes on to the source, so the ground track nearest the source needs the input current and not the sum. A linear regulator's ground is counted for about twice what flows to the source. The conservative figure was chosen over guessing the topology of the ground.

**Each current once.** A module's port stands for what is inside the module (ADR 0007) and the rails and parts inside it are the same current seen closer up. Where something modelled inside a module is on the net, the module's port on that net is left out and the inside counts; a module with nothing modelled inside on the net keeps its port, which is all that is known of it. Without this the `sw` rail of a buck converter, a module port and an IC rail on the same node, was counted twice, and so was the converter's output through the inductor's end and the module's port.

**Regulators.** The input current of a regulator comes from the power balance, never from its output current. The solver already works it out and lowering uses it (the `current` of the regulator's input rail): a `LinearRegulator` states `.vin.current == -.vout.current`, and a switching regulator's IC states `.vin.current == -.buck.sw.current * .buck.sw.voltage / (.vin.voltage * .buck.efficiency)` (ADR 0025), so a 1 A, 1.8 V output from 4.75 V at 85 % efficiency draws 0.459 A at its input; the input net is sized for that and the output net for 1 A (a test in `crates/netsmith-lower/tests/guidelines.rs`). The quiescent current is not added: the library's models have no figure for it (ADR 0025 ignores it) and one is not invented here; a part that states its `vin.current` with a quiescent current is used as stated. A switching regulator whose part states no efficiency leaves the input current unknown (the solver leaves a net with two unknown currents unsolved, issue #18), and the next paragraph applies.

**A current that is not known stays unknown.** A net with any carrier whose current has not been worked out is not sized, and the note of the first amendment names the net and the carriers: ``the current of rail `u.vin`, ... is not known (...), so the tracks of net `VIN` are not sized from their current``. A lower bound from the others is never used to size it. The check of a stated `.min_track` still runs against the known part of the sum.

**A stated `.min_track` stays an override** and is checked against the sum: 1 mm on a ground that carries 3 A is a finding (it carries 2.39 A at 10 K). No new syntax.

**Choices made without the owner, to be reviewed.** The larger of the two sums rather than the load side alone; a module's port left out only when something inside it is on the net; the pessimism at a regulator's ground left as it is; no quiescent current added. The IPC constants are as in the first amendment (provisional).

**Examples.** None of the examples in `examples/` changes its widths or notes: their currents are milliamps, at the process's least track.

## Amendment 3: a net with a current that is not known is sized for the known part (PROVISIONAL, awaiting the owner's review)

Found on a real 12 V automotive board: a net `+3V8` carried a modem load of 1.2 A that was stated and a divider resistor whose current the solver could not work out (the solver leaves the currents of a net with two or more unknown ones unsolved, issue #18). The first and second amendments left such a net at the process's least track, 0.09 mm, and then warned that 0.09 mm carries 417 mA against the 1.2 A that was known. The tool drew a track it knew to be too narrow, and warned about it, because it would not size from a partial sum.

**The change.** The currents that are known are a lower bound on the net's current: loads only add up, so a current that is not known can make the sum larger and never smaller (it holds for the larger of the two sums too, since each side only gains terms). Drawing the net at least as wide as the known sum needs is therefore not a guess. When some currents on a net are not known and no rail states a `.min_track`, lowering gives the net the width IPC-2221 needs for the sum of the known currents, rounded up to 0.01 mm, whenever that is more than the process's least; otherwise it stays at the least. A net where every current is known behaves as before. This replaces the paragraphs "A current that is not known" of the first amendment and "A current that is not known stays unknown" of the second, which refused to use the known part.

**The note stays, reworded.** `build` and `fab-notes.txt` still print a note, per net with a missing current, naming the net and the carriers whose current is missing, and now say the width is a lower bound: `... so the tracks of net `GND` are 0.39 mm, a lower bound: sized for the 1.2 A that is known, not for the whole current; state that current, or give a rail on the net a `.min_track``, or `are the process's least, 0.1 mm, a lower bound: no current on the net is known` (or `it carries the 5.01 mA that is known` when the known current needs less than the least). It is still a note and not a guideline: it does not change with `--strict`, because the person has nothing to correct in a finding the tool cannot make beyond stating the current. A rail that states a `.min_track` on the net has decided the width and gets no note, as before.

**The guideline fires only against a stated width.** A net the tool sized, or left at the least that the known current does not exceed, is never too narrow for what is known, so it has no finding. A width the board stated (`.min_track`) that is below what the known current needs is still a finding, as for any net, worded `carries at least N A` (and not `up to`) with the sentence `the current of ... is not known, so it may be more`, because the sum is a lower bound there.

**What it costs.** The lower bound can be far from the truth and the note says so; the width is the least the net can have, not the width it needs. A board with a missing current draws wider nets than before, which can make a tight board harder to route, as for any sized net. The alternative that was rejected is the choice of the earlier amendments, to leave the net at the least and say so: it produced a known-too-narrow track and a warning the person could only silence by stating a width, which is the failure issue #4 set out to remove. Also considered and rejected: sizing for a guess at the unknown current (a guess is as likely too narrow as too wide, the reason of the first amendment), and a finding that fails the build.

**Left open.** Whether a net whose rail states a `.min_track` should also get the note when a current on it is not known (it does not today; the guideline names the missing carriers instead). Whether the note should be a guideline that `--strict` can turn into an error. Both are the owner's. The code is `plan_tracks` in `crates/netsmith-lower/src/guidelines.rs`; the tests are in `crates/netsmith-lower/tests/guidelines.rs`.

## Consequences

Boards that were silently under-width now warn. None of the examples did. A project that wants the check to block puts `guidelines = "error"` in its manifest. `Temperature` is a new type name in the language (kelvin only; no temperature curves yet).
