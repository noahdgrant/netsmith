# netsmith's own design rules check

The status line it had said "accepted (owner review 2026-11-04)", and the text says the owner "reviewed the choices below on 2026-11-04 and accepted them". Meets test 2 (the check reads the `.kicad_pcb` text and not the `Board`, which the obvious reading of the code gets wrong) and test 3 (`kicad-cli` as the only check is the alternative someone will propose again). The text before the cut is `git show 0eaf326:docs/adr/0037-netsmiths-own-design-rules-check.md`. The list of rules, the geometry, what KiCad's comparison taught, the corpus it was checked against and what is not checked are the header of `crates/netsmith-fab/src/drc/mod.rs`; the tests are `crates/netsmith/tests/fab.rs`, `crates/netsmith-fab/tests/drc_corpus.rs` and `crates/netsmith-pcb/tests/kicad_drc.rs`.

ADR 0021's direction says netsmith must not need KiCad installed. ADR 0034 made the fabrication files netsmith's own and left the design rules check to `kicad-cli`: without KiCad `fab` refused to package, or packaged with a note that nothing had been checked.

**Decision.** `crates/netsmith-fab/src/drc/` checks the board over the `.kicad_pcb` text and the `.kicad_pro` beside it, and `fab`, `fab --order` and the editor's Fab button gate on it. A finding is data: a rule (named as KiCad names it, so the two reports compare), a severity, a message with the numbers, a place and the items. The numbers are the project's, and one a file lacks is KiCad 9's default. The project's `rule_severities` decide what stops `fab`: the exporter writes `silk_over_copper`, `silk_overlap`, `silk_edge_clearance` and `solder_mask_bridge` as warnings (a fabricator clips silkscreen over a mask opening and keeps a web only where it can; neither stops a board being made) and everything else as errors. The owner confirmed on 2026-11-04 that those four stay warnings. `--allow-drc-violations` waives errors and never a placement requirement (ADR 0045 section 8). KiCad's check stays as a witness (`fab --cross-check`, the tests) and as a second opinion in the editor.

**Why in `netsmith-fab` over the file.** The package, the Gerbers and the cross-check already work from the file through one reader, so the check sees exactly what the board house will make, and a board ported from KiCad is checked like one netsmith wrote. `package` calls the check directly, and a separate `netsmith-drc` crate would have to sit above `netsmith-fab` (it needs the reader, the font and the outline), so `package` could not call it. KiCad reads the same two files, so the two checks can be compared on identical input. The editor writes the file in memory and checks that. The `Board` model's own `check_placement` stays and is not replaced.

**Rejected.** `kicad-cli` as the only check, which needs KiCad on the machine. A check over the `Board` model in `netsmith-pcb`, which would not see a board ported from KiCad and not what the writers make. Checking a pour's fill: netsmith's fill is "everything but the clearances" by construction, so the pour is never checked against other copper.

**The cost.** Rules that are not KiCad's (`hole_to_edge`, `via_in_pad`, `constraint`, and from the placement check `too_tall` and `height_unchecked`) are counted by the cross-check and not compared. The check agrees with KiCad's on a corpus of 28 broken boards and on 37 boards of `netsmith-pcb`'s tests, and it does not check what KiCad calls `isolated_copper`, `starved_thermal` and `copper_sliver`, so the gate can pass a board that KiCad flags in those categories. Impedance rules, differential pairs and lengths, custom rules (`.kicad_dru`), blind, buried and micro vias, stackup rules and the electrical rules check are not covered. Silkscreen text uses netsmith's own font, so a text that only just clears a pad can be judged differently.

**Left open.** JLCPCB's own check has not been run on a package: the cross-check says netsmith agrees with KiCad, not that a fabricator will accept the board.
