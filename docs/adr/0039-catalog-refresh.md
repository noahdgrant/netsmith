# `netsmith catalog refresh`: an opt-in check of catalog rows against LCSC's record

Extends ADR 0022 (catalog files) and ADR 0019 (the editor). Nothing here changes what the solver reads: its input is still the CSV files, and it never needs the network.

## What it does now

`netsmith catalog refresh` is the only command that touches the network. `build`, `fab`, `compare`, the solver, the editor's live checks and the tests do not. The editor's "Check parts against LCSC" button runs the same code over the project's own catalog files (`POST /api/catalog/refresh`).

For each row with an `lcsc` number it asks LCSC's product record (`GET .../ftps/wm/product/detail?productCode=C25104`) and compares two things: the manufacturer's number (`productModel`) with the row's `mpn`, and the package (`encapStandard`) with the row's `package`. The suppliers spell packages their own way (`SOT-23-3L` for `SOT-23`), so the row's package may be the supplier's or one of its words, with a trailing `-<digit>L` removed. The manufacturer's number is the real check. The package only catches a number reissued for another package.

- **VERIFIED** when both agree. **CONFLICT** when either differs, with both values. **MISSING** when LCSC no longer lists the part. **SKIPPED** with `--offline` when no answer was kept. The exit code is 1 for a CONFLICT or MISSING and 2 when the run had to stop.
- **A refresh writes one cell: `checked`**, the day (UTC) the row last verified, or with `--offline` the day the kept answer was got. It writes it only if the file has the column (the thirteen standard files do, empty). Nothing reads `checked`. It exists so a diff and `git log` show which rows were last verified.
- **It never writes `price`, `stock`, `price_breaks`, `library`, `date` or any other cell.** They are JLCPCB's numbers, entered by hand from its parts page (`data/jlcpcb/README.md`), and LCSC's differ. A test asserts that every cell but `checked` is byte-identical after a refresh of every row of every standard file, against a fake LCSC that lists a different stock and price for each.
- **CONFLICT and MISSING rows are reported and never changed or deleted.** Removing a row is a person's decision, and `considered.csv` is where it goes.
- **JLCPCB is not asked.** No request goes to a JLCPCB host or an `/api` path. The fetcher refuses such an endpoint, even if `NETSMITH_LCSC_URL` names one, before it sends anything. JLCPCB data is not fetched, and the output says so (`refresh::NOTICE`).
- **A note, not a finding:** when LCSC lists stock 0 where the row has some or none, or the row has 0 and LCSC lists some, the report says to check JLCPCB's parts page by hand. The exit code is unaffected. LCSC's prices are not read.
- **The file is edited in place.** Only the `checked` cell changes, by byte span, so a refresh is a diff of those cells and nothing else. The rows are never reordered. Files are written after every row has been looked up, each by a rename of a finished temporary file, so a run that stops writes nothing.
- **Selection:** `--dry-run` prints the diff and writes nothing; `--only <catalog>` and `--lcsc <C123>` choose catalogs and rows. With no path the files are the project's `catalogs` and, in the netsmith repository, `data/jlcpcb/catalog/`. The standard catalogs are also inside the binary, which cannot be written, so they are checked in the repository and reach users with a release.
- **Polite, and honest when it cannot be.** One request at a time, 500 ms apart (`--delay`). A User-Agent that says what it is (`netsmith-catalog-refresh/<version> ... one request at a time`). A cache of the answers (`$NETSMITH_CACHE_DIR`, else `$XDG_CACHE_HOME/netsmith`, else `~/.cache/netsmith`, in `catalog-refresh/`) used for 24 hours (`--cache-ttl`, `--no-cache`). `--offline` asks nothing and uses kept answers of any age. A retry with a doubling wait (2 s, 4 s, ...; a `Retry-After` is honoured up to a minute) three times after a dropped connection, a 429 or a 5xx. A stop, naming the endpoint, on a 403 or another refusal, a web page where JSON should be, or JSON of another shape. On a stop nothing is written. An LCSC number is sent only if it is `C` and digits. `NETSMITH_LCSC_URL` points the command at another address (a mirror, a proxy of your own, the tests' fake server).
- **`netsmith catalog age [--days N]`** (default 90) lists the rows whose price and stock (`date`) are older or missing. A refresh never changes `date`, so it never makes a row less stale. ADR 0047 ages a provider's quotes, and the standard catalogs ship no price, stock or date.

## What is still unsettled

**LCSC's terms of use are unread.** LCSC's `robots.txt` has no rule for the path of the product endpoint, but the endpoint is unofficial (the one the lcsc.com pages call), the repository has never agreed anything with LCSC, and the sites' general terms could not be read (the pages are rendered by script). The measures above (opt-in, sequential, a pause, a cache, an honest User-Agent) are courtesy and not permission. A person must read LCSC's terms before the command is advertised beyond this repository, and the command and the editor's button should be withdrawn or changed if they forbid it. The official APIs (JLCAPI at api.jlcpcb.com; the LCSC API, free with an account and a review) need the user's own accounts, come after v0.1.0, and would let a refresh fetch JLCPCB's own price, stock and library. Until then those three are read by hand.

## The editor

The bill of materials shows the date of each line's price and stock under the price, with the age in a tooltip, and marks a line older than 90 days (the number `catalog age` uses) in amber with a dot in front of its designators. A chip above the table counts them. `Bom` carries `staleAfterDays` and the project's own catalog files, and each `BomLine` its `date`, `ageDays` and `stale`, computed on the server (typed in `api.rs`). The route needs the `X-Netsmith` header, reports each looked-up part over the WebSocket as `progress` of task `catalog`, and answers with a `CatalogRefresh` (the rows needing a look, how many were verified, whether the files were written, the summary, or the reason it stopped). The file watcher then builds again; the bill does not change, because only `checked` was written. "Preview only" is `--dry-run`; "offline" is `--offline`. A project that lists no catalogs is told so.

## Consequences

- No new way to say a price: it is still the CSV cell, entered by hand. A refresh is a diff of `checked` cells that a person reviews and commits.
- A new dependency, `ureq` (with rustls), in the `netsmith` crate only. The solver, the language and the checker have none.
- The tests never reach the network. A server on `127.0.0.1` answers from `crates/netsmith/tests/fixtures/catalog-refresh/`: the responses of twelve parts captured once from the live endpoints on 2026-11-02 (public data) and reduced to the fields netsmith reads, because the full answers carry signed, expiring download links and images. The JLCPCB captures were deleted afterwards. Another test builds answers from the rows of every standard file and checks that a refresh changes nothing but the `checked` cell.

## Not decided here

- Whether to refresh the standard catalogs on a schedule, or on a release, and who commits them.
- Showing a live price in the editor without writing a file, for a part of the standard catalogs.
- A second supplier (Mouser, Digi-Key, which have official APIs and keys), or the official JLCPCB and LCSC APIs. The code has one place that reads a record, which is where another would go.

## How it got here

**The first version (2026-11-02, chosen by the agent from the user's task, awaiting review).** The user suggested an online pricing feature, opt-in, because a catalog row's `price`, `stock` and `library` are a snapshot that goes stale (a part sells out, JLCPCB moves it between Basic and Extended, a price changes), and the only fix was a person repeating the fetches in `data/jlcpcb/README.md`. The command was built as an update. Ten items were decided:

1. A command, never a side effect (kept, above).
2. It read two records for each row: the JLCPCB parts library, searched by keyword (the record taken is the one whose `componentCode` is exactly the number; it gave the library, `stockCount` and `componentPrices`), and LCSC's product record (the manufacturer's number and the package).
3. It wrote `price` (the first quantity break), `stock` (JLCPCB's), `library`, `date` (the day the answer was got, UTC) and `price_breaks` if the file had the column. Never an electrical column, a name, a source or a note. A cell that already said the same number was not touched.
4. A row that did not match (a different manufacturer's number, or a package the suppliers do not both give) was reported CONFLICT, and a part with no record MISSING. Neither was deleted (kept, above).
5. The file was rewritten by editing cells in place, never reordering rows, since the order of rows is the selection policy (ADR 0022). When new prices put rows out of Basic-first, cheapest-first order, the command said so and did not move them. Files were written only after every row was looked up (kept, above).
6. `--dry-run`, `--only`, `--lcsc`, the default paths and `catalog age` (kept, above).
7. Polite and honest: the delay, the User-Agent, the cache, `--offline`, the retries and the stops (kept, above), with two endpoints and `NETSMITH_JLCPCB_URL`.
8. The terms of use were not settled (kept, above, now for LCSC alone).
9. A row whose `stock` cell is `0` was not offered by the solver. This amended item 6 of ADR 0022, and made a refresh that finds a part sold out safe to run. It was amended twice on 2026-11-02 (the stock was LCSC's for a few hours, then the hand-entered JLCPCB number again; a refresh never wrote it again), and ADR 0047 withdrew it on 2026-11-03: the solver does not read stock, and a row is offered whatever its stock cell says.
10. A fixed column `price_breaks` (`1:0.0019 1000:0.0015`), written by the refresh from LCSC's price ladder. ADR 0047 made it a hand-entered column like `price`, and nothing reads it.

**The first 2026-11-02 decision: JLCPCB is not asked.** The maintainer read the `robots.txt` of both sites. JLCPCB's disallows automated clients on the path its parts library is served from, which the request of item 2 used. LCSC's has no rule for the path of its product endpoint. The user decided, for v0.1.0, to drop the JLCPCB endpoint and keep LCSC's only, to tell users that JLCPCB data is not fetched, and to take the official APIs after v0.1.0. The JLCPCB request was deleted, `NETSMITH_JLCPCB_URL` is no longer read, and the fetcher refuses a JLCPCB host or an `/api` path. A test shows the fake server was asked only `GET /lcsc?productCode=C...`, for every row of every standard file. LCSC's record gave the manufacturer's number, the package, `stockNumber` and `productPriceList`, and no library type. For a few hours the refresh then wrote LCSC's price (the first break), stock and `price_breaks` and the `date`, and reported the `library` as not fetched. This was a choice among three: write nothing and refresh only the checks; write LCSC's numbers and say so; or leave `price` and `stock` and add columns. The second was taken because the user's rule was to refresh what the LCSC response honestly contains.

**The second 2026-11-02 decision: a check, not a data update.** Later the same day the user decided that the board is assembled from JLCPCB's own parts library and that LCSC's price and stock differ from JLCPCB's: for C25104 LCSC lists 1,085,700 in stock where JLCPCB lists 2,059,008, and LCSC's first price break is at 5 to 100 pieces where the rows hold the one-piece price. The solver, the bill of materials and the stock-0 rule read `price` and `stock` as the board house's numbers, so writing LCSC's into them put the wrong supplier's numbers where the right one's are expected. So a refresh became the check described at the top, the statuses `UPDATED` and `CONFIRMED` went with the only thing they described, and `checked` became a new fixed column. It is not the `date` column because `date` means the day the `price` and `stock` were read (the bill of materials shows it under the price and marks a line stale from it, and `catalog age` lists rows by it). Verifying a part's identity says nothing about whether the price is current, so moving `date` would make a stale JLCPCB price look fresh. One meaning for each column (ADR 0001), so the second date has its own column. Recording nothing was rejected: the check is the part of the refresh that is of use, and a person wants to know which rows have been through it. The stock-0 rule stood on the hand-entered stock until ADR 0047. The editor's button went from "Refresh prices" through "Refresh prices from LCSC (not JLCPCB)" to "Check parts against LCSC". The route and the command kept their names. Withdrawn by the same decision: the plan for C25102 and C47339, which JLCPCB flags Preferred, to change from `Extended` to `Preferred` on the first refresh. The `library` is not fetched, so they stay `Extended` until a person or an official API says otherwise.

**ADR 0047 (provisional, 2026-11-03).** Price, stock and date are a provider's quotes and not part of a catalog row. The standard files ship them blank, the solver never reads them, and `catalog age` ages quotes. The identity check against LCSC and `checked` stay as this ADR describes them. Reviewed by the owner on 2026-11-04, who asked for this rewrite and no new decisions.
