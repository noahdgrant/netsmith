# Self-contained libraries: symbols, footprints and the schematic netlist without KiCad

The status line it had said "accepted (user decisions 2026-11-02)". Meets test 1 (projects' mappings and exported files depend on where libraries come from) and test 3 (the options below). The text before the cut is `git show 0eaf326:docs/adr/0041-self-contained-libraries.md`. The inventory, the licence reading and the plan for reading a `.kicad_sch` are `docs/research/kicad-library-licensing.md`. ADR 0097 (accepted) continues this ADR, rejects fetching and bundling, and decides what it left open: the symbols, and the footprints no generator makes. It answers questions 1 to 6 below, as each says. ADR 0043 carries out the footprint decision.

ADR 0021 says a person with the `netsmith` binary alone must be able to write, check, solve, see and fabricate a design. ADR 0034 and ADR 0037 removed `kicad-cli` from that path. Two dependencies were left: the symbol and footprint libraries, read at run time from the installed KiCad, and `netsmith compare` on a `.kicad_sch`, which asks `kicad-cli sch export netlist`. The `.kicad_sch` and `.kicad_pcb` netsmith writes are an export and stay.

**Decision (the user, 2026-11-02), word for word:** "netsmith generates footprints itself (original generators for common packages, IPC-7351 style, checked against KiCad's own footprints to 0.01 mm) rather than depending on KiCad's library bytes. KiCad's `.kicad_sym`/`.kicad_mod` stay the file format. Packages without a generator still need a library file: until the owner decides otherwise, those come from a project's own libraries or a `libs fetch` from KiCad's repository into a cache (nothing is bundled in the binary). Symbols: simple generated symbols for the standard kinds; the editor draws symbols from its own data."

**One library format.** Keep KiCad's two formats and add none of our own: one way to say a thing (ADR 0001); the export embeds each symbol and footprint verbatim, so a native format needs a converter each way and a lossless round trip, where the loader and emitters already exist; everything arrives in that format (manufacturers' downloads, `easyeda2kicad`, KiCad's editors); and size and speed do not call for one (the standard rows are about 320 kB, a good product a few MB).

**Rejected, and why.** Bundling a subset of KiCad's libraries (A): they are CC BY-SA 4.0 with an exception for designs and generated files only, a subset or a flattened symbol is a redistribution, and whether a binary that embeds them is one is not settled by the text read. Fetching on first use (B) as the only answer: it needs the network once, and a person with the binary alone has no working tool before it. Netsmith's own drawings (C) for everything: a footprint that is slightly wrong makes a bad board, so C is built only where it is tested against KiCad's own to 0.01 mm. Translating `kicad-footprint-generator`'s Python: it is GPL-3.0-or-later. A format of our own: above.

**The cost.** Until generators and drawn symbols cover a design, a package without one needs a library file in the project or a fetch (ADR 0097 rejects the fetch), and a fetch needs a lock file, pinned commits and per-file checksums (an installed KiCad can only be pinned by what upstream holds: installed `Device.kicad_sym` differs from upstream 9.0.9.1 in 644 lines). The recommended `libs fetch`, `libs vendor` and a `.kicad_sch` reader were never built, and their staged plan belongs in issues #5 and #61 and not here.

**The seven questions**, word for word, and where each stands:

1. "**Licensing choice.** Is netsmith allowed to ship any KiCad library bytes (option A, inside the repo or the binary)? If yes, in a separate directory with CC BY-SA 4.0 and a `NOTICE`, or in the binary too? If no, option B (fetch) only. The text read cannot settle whether a binary that embeds the files is a redistribution of them; an independent opinion should be taken if A is chosen. Also: should the repository get a `LICENSE` file for the MIT code?" ADR 0097 answers it: netsmith ships none of KiCad's library bytes, and fetching is rejected too. The repository has a `LICENSE` file.
2. "**Footprints and symbols of our own.** Should netsmith also generate footprints (and draw the simple symbols) itself, for the common packages, tested against KiCad's? This removes the bytes question for those parts and gives a no-network floor, but costs a week or more and carries the risk of a wrong pad. Is the IPC-7351 route acceptable (IPC documents are paid), or should the dimensions come from manufacturers' drawings, package by package?" ADR 0097 answers it: netsmith carries its own symbols and footprints, from package drawings and IPC-7351B, tested against KiCad's. Whether the IPC tables can be read freely is for a person (ADR 0043; issue #10).
3. "**Which libraries and version to pin.** KiCad `9.0.9.1` (the newest 9.0 tag found) for symbols and footprints, or the version the owner's KiCad is? The installed copy on this machine is a 9.0 build whose `Device` library differs from `9.0.9.1`. Only the libraries the std rows name, or the stock libraries in general (every user project that names a stock `Library:Name` would then fetch more)?" ADR 0097 answers it by not fetching: nothing is pinned, and an installed KiCad or a project's own library is an optional source.
4. "**Where the cache lives.** `~/.cache/netsmith/kicad-libs/<tag>/` (per user, shared by projects), or a folder in the project (`.netsmith/libs/`, ignored by git), or both with the project's winning? The proposal is per user, plus `libs vendor` for the project." There is no cache, since there is no fetch (ADR 0097).
5. "**Offline use.** Is a first-use download acceptable for 'the binary alone is enough', or must a fresh binary work with no network? If the latter, stage 6 or option A is required, not optional, for at least the examples' parts." A fresh binary works with no network (ADR 0097).
6. "**Project versus user.** Should a project always vendor what it uses (and commit it), so that a design is reproducible from its repository without a fetch, or is a lock file enough? Vendoring makes the project carry CC BY-SA files, with their notice, in its own repository (the design exception covers the design and its generated files, not the library copies themselves)." With no fetch there is no lock file, and `libs vendor` is not built. A project that wants KiCad's files lists its own `[[library]]` (ADR 0097).
7. "**LCSC and EasyEDA parts.** Should a later step import a part by LCSC number into a project library (the atopile route)? It is outside this ADR, and the data's terms of use have to be read first." Not built. A person must read the terms of use first (checklist in issue #10).
