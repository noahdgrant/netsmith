# Generated footprints

The status line it had said "provisional". The text does not say that the owner accepted this ADR, only that it "carries out the user's decision recorded in ADR 0041", so it is `proposed`; the owner may accept it. Meets test 1 (every board's footprints come from it) and test 3 (KiCad's library bytes are the obvious alternative). The text before the cut is `git show 0eaf326:docs/adr/0043-generated-footprints.md`. The families, the formulas, the sources, the lookup order, the validation and what is not generated are the header of `crates/netsmith-pcb/src/generate/mod.rs`; the test is `crates/netsmith-pcb/tests/generated_vs_kicad.rs`; the files netsmith ships for packages no generator makes are `std/libs/README.md`.

**Decision.** netsmith makes the footprints of the common packages itself: chips, diodes, SOT, SC-70, SOIC, TSSOP, MSOP, SSOP, QFN, DFN, QFP, DPAK, D2PAK, SOT-89, crystals, BGA on a full grid and pin headers, 855 names in all. A generator turns a package's parameters into a `Footprint`, writes the text of a `.kicad_mod` and reads it back with the loader, so nothing downstream can tell it from a read one. It answers to the name KiCad gives the footprint, so the mapping names it as before. Pads follow the land pattern formulas of IPC-7351B at nominal density, with the courtyard 0.25 mm outside pads and body. **The generator wins for the names it makes**, so a build gives the same pads on every machine whatever KiCad is installed, and they do not move with a KiCad patch release. A name outside the list is not generated, and a project library named like a generated one is refused. A design that uses only generated packages needs no footprint library.

**The check.** A generator is tested against KiCad's own footprint of the same name: pad count, numbers, shape, layers, hole and box of every pad, and the courtyard, within 0.01 mm. A difference needs an entry in the test's `DIFFERENCES` with its bound and reason, and an entry nothing needs fails the test. 775 of 855 agree; the 80 that differ are 2.54 mm pin sockets, by 0.05 mm in the courtyard. A family row is kept only if it agrees; the rest are left to the library and not tuned. A wrong pad is a wrong board, so the check matters more than the generator.

**Rejected.** Bundling KiCad's footprints: CC-BY-SA 4.0, and whether a binary that embeds them is a redistribution was not settled (ADR 0097 has the reasoning). Translating `kicad-footprint-generator`'s Python into Rust: it is GPL-3.0-or-later, so the Rust would be a derivative, so the generators work from the IPC formulas and the package drawings.

**The cost.** netsmith owns a drawing of every package it makes, and each new row must agree with KiCad's footprint or say why not. Silkscreen and text positions differ from KiCad's, and pads differ by less than 0.01 mm. Without KiCad installed the check cannot run (CI without it skips). Some generator inputs were fitted to reproduce KiCad 9.0's pads and not read from a datasheet (the QFP lead widths, some TSSOP spans), and the SC-70 rows agree with KiCad 9.0.0 and not with 9.0.7.

**Left open**, and the owner's. Word for word: "Whether reading GPL code to learn a published formula taints what is written is the owner's to judge; the formulas are IPC's." The Python of `ipc_pad_size_calculators.py` was read to learn the formula for the span of a lead, the exposed-pad clearance rule and the paste coverage; the Rust shares no code or structure with it. And, from ADR 0041: whether the IPC-SM-782 tables "can be read freely" (IPC standards are paid documents), and whether pad geometry computed from the IPC formulas can be freely reproduced. Also open: whether a BGA grid with balls left out can be a rule; the families that grow one validated package at a time; and the status of this ADR itself.
