# Price and stock come from a provider when the bill of materials is made, and passives are generic until a later step resolves them

Meets tests 1 (`[supply]` in `netsmith.toml`, the quote file and cache formats, and the removal of price and stock from the solver are interfaces users' projects depend on) and 3 (a price in the catalog files, and a solver that only picks values with a row, are the obvious alternatives). Issues #8 and #9. `proposed`: the status line said "provisional (written by the agent ...; to be reviewed by the maintainer)", and the owner decided only the items marked below. The text before the cut is `git show 3e54ce1:docs/adr/0047-supplier-data-comes-from-a-provider-and-passives-are-generic.md` (183 lines: the audit of how the solver picks, the interface, the cache, the first implementation, the generic capacitors, inductors and LEDs, and the open questions).

**The problem.** A catalog row mixed what a part is with what a supplier says today. The second goes stale within days, the suppliers' terms are unread, and every standard row counted as "undated". The solver could only pick a value that has a row, so a value nobody stocks blocked the build although any resistor of that value would do. A row with `stock` 0 was dropped silently before the search, so a design that built last week might not build today. The solver's policy is the file order and nothing else (ADR 0022 item 6), which encoded prices nobody can re-check.

**Decision.**

1. Identity stays in the repository; price, stock and date do not. A row keeps `lcsc`, `mpn`, `library`, `package`, the values, `source` and `checked`. A file that still has the price columns is read as the last resort of the chain. The solver never reads them, and the stock-0 rule of ADR 0039 item 9 is withdrawn. This replaces ADR 0022 items 4 and 6 and ADR 0039 items 9 and 10; the refresh stays as the identity check against LCSC.
2. A price comes from a `SupplyProvider` (`crates/netsmith/src/supply/`) when the bill of materials or `fab` is made, and is kept in a cache. A quote says which stock it is (`jlcpcb-assembly` or `lcsc-retail`), because the two differ for the same number. A part with no quote has price and stock **unknown**, which is never 0 and never guessed from a neighbouring row. The formats are interfaces: the quote file `lcsc,mpn,channel,stock,price_breaks,currency,date` and the cache `lcsc,mpn,channel,stock,price_breaks,currency,fetched`; the rules (24 hours, 90 days, the older answer used when offline) are in the header of `supply/mod.rs`.
3. A project names its provider in a `[supply]` table (`provider`, `file`, `channel`, `cache_hours`). The manifest has no field for a key's value; a credential is given by the name of an environment variable (owner, 2026-11-03). The series of generic parts is the `series` key of `[project]` (owner, 2026-11-04). A quantity below the first price break shows the first break's price, marked "from N pieces", and the cache lasts 24 hours and a price is stale after 90 days (owner, 2026-11-04).
4. The solver may pick a **generic part**: a value of the series with a tolerance, a package and a rating, no supplier and no part number. **Resolution** is a separate step: it picks the row of the same catalog that is at least as good (Basic, then Preferred, then Extended, then file order), passing over a row a provider says has no stock. A part no row fits is unresolved, and `fab` refuses it by name with the three nearest rows and the result of the checks with each.
5. A generic ceramic capacitor resolves only to a row with a recorded DC-bias curve; with none it is unresolved, by name (owner, 2026-11-03). No conservative curve and no derating rule.
6. Nothing contacts a supplier. A real provider waits until the maintainer has read the supplier's terms and the official API's licence; JLCPCB's `robots.txt` disallows `/api`.

**Rejected.** Price and stock in the catalog files (stale; ADR 0039 ended with blank cells). A provider in a user-level file only, with the channel in the manifest (the owner chose the table). A statement in the language for the series. A conservative bias curve for a generic capacitor (a modelling invention, so no row is guessed to have one). Converting currencies, and a price from a nearby row.

**The cost.** Two new interfaces to keep honest, the quote file and the cache. The generic parts come after the rows, so a row that serves is taken first, and a generic capacitor, inductor or LED is mostly *unresolved*, listed with its near rows: useful, but the end state (the solver picks generic parts only, resolution picks the row) would change which part existing designs get. A standard catalog never goes stale, and a design builds the same offline and online.

**Left open.** Word for word where quoted. The mechanism is in `supply/mod.rs`, `resolve.rs` and `crates/netsmith-solve/src/generic.rs`, with the longer lists in their headers:
- "Generic parts appended after the identity rows or instead of them? Appended keeps every design as it is; instead is the clean model and changes which part existing designs get." Issue #33 records "appended" as decided on 2026-11-03; this text does not.
- "Is "JLCPCB Basic, then Preferred, then Extended, then file order" the preferred-parts list, or is it a file of its own (`preferred.csv`, a project's list that wins)?"
- "Which real providers, and in which order: the LCSC API, JLCAPI, an aggregator (the Nexar API ...) or a community snapshot (the KiCad JLCPCB plugin downloads one daily). Each needs the maintainer to read its terms and to decide whose key a user brings."
- "Should the editor offer a swap with the checks run for each alternative, and should `fab` refuse an unresolved part (this ADR says it does) or build without it?" The checks are built; the swap is not.
- "The shipped `price`, `stock` and `date` columns: keep as the `catalog` provider's input (this ADR), or remove the columns from the format."
- The user-level credentials file (`$XDG_CONFIG_HOME/netsmith/supply.toml`) and the spelling of the manifest field that names the variable (for example `key_env`) were not part of the owner's answer; neither is built.
- The generic capacitor, inductor and LED choices are the agent's and **provisional**: five assumptions to confirm (the series of a capacitor, the packages and tolerances, `Stated` for an LED, a rating left unknown, the cap of 30 re-solves), in the header of `generic.rs`, with the gaps in the catalogs (no LED maximum current, no inductor rms current, no capacitor dielectric).
- Not built: a provider that asks a supplier, `--offline` for the bill and `fab`, a named preferred-parts file, the quantity of an order across boards, and the editor's swap.
