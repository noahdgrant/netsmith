# The editor compares the project with a git ref and tells what changed in the circuit

Meets tests 2 (a text diff is the obvious reading and it is wrong for a circuit) and 3 (a text diff, and a checkout of the ref, are the obvious alternatives). The status line said "accepted (owner review, 2026-11-06; as proposed: the endpoints' contract and the identity rules are written down for the page that is built on them)". The owner accepted the choices under "Choices" as built on 2026-11-11. The text before the cut is `git show 31d3394:docs/adr/0059-the-editor-compares-the-project-with-a-git-ref.md`. The contract is the header of `crates/netsmith-editor/src/api/compare.rs`; the identity rules and the sentence are the header of `crates/netsmith-workspace/src/diff.rs`; how a ref is read, kept and limited is the headers of `git.rs` and `compare.rs` beside it.

**Decision.** In a code-first tool the design lives in git, so the question an engineer has about a branch is "what did it change in the circuit?" and not "which lines?". A text diff answers the second: a renumbered designator rewrites nothing in the source and renames half the parts in the schematic, and a changed `.current` rewrites one line and moves a resistor, an LED and a rail's headroom. The editor therefore compares the circuit. The project as it is at a git ref (the base) is reduced to parts, nets, rails, ports, systems, the PCB, bill of materials and problems, compared with the files on disk (the head) or with a second ref, and the differences are listed with the source line of each on both sides and one sentence (`3 parts added, 1 removed, 2 values changed, 1 rail's headroom shrank from 80 mA to 20 mA`). It is the one view that is about two readings of the project.

**Identity is what the design called, never what a tool numbered.** A part is its path in the board; the designator is a field, so a part that differs only by designator is renumbered and listed apart. A part gone from one path and new at another with the same kind, value, package and named nets moved. A net is its name, and a renamed net is found by its pins (the same pins, or at least half of the larger side's), which are named by the paths of their parts. A rail is the power tree's node for its net; a module and a port are their paths; a board is its name. The exact rules are in `diff.rs`.

**How the ref is read.** Through the `git` command line, never a library: libgit2 or gitoxide would be a large dependency for six commands, and none of them gives what the analysis needs, a folder of files. The ref's files are written by `git archive | tar -x` into a scratch folder that is removed when the comparison ends, so the work tree, the index and the refs are never touched. The scratch folder gets a `Workspace` of its own that runs the same analysis as the live project and is reduced to a digest; the digest is kept by commit hash. A ref's files are not trusted: links, special files and files over 8 MB are removed before the analysis, and a ref over 256 MB is refused.

**Rejected.** A text diff of the sources: it is `git diff`, and it cannot say that a rail lost headroom. Reusing `netsmith-netlist`'s comparison: it compares two graphs that share no names, by refining colours, which is what a port from KiCad needs, while here the parts have paths on both sides. A `git worktree add` or a checkout in a temporary folder: they write to `.git` (`worktrees/`, the index, hooks) and a checkout may run filters and hooks. Keeping the whole `Snapshot` of a ref: it holds the drawings and the models, megabytes per board, for what the digest holds in kilobytes. A start and a poll: the long jobs of the editor are one request with progress on the socket, and a compare is one more.

**The cost.** A ref is analysed, so the first compare of a ref takes the seconds an analysis takes (35 ms against 1.1 s for the small example once it is kept). The comparison is by what the bill groups parts by, so a changed manufacturer's number alone shows as a changed line. `git archive` honours `export-ignore`, so a project that excludes its sources from archives is read without them. Panels are not compared, and the schematic of the base is not drawn. A server killed in the middle of a compare leaves its scratch folder until the next editor starts.

**Choices.** Each was a default the author took, word for word from the text before the cut. Accepted as built by the owner, 2026-11-11.
- What is the same part, net and rail on both sides: the rules of "Identity" above and `diff.rs`.
- A part the placer chose on both sides (`derived`) is never listed as moved: "the placer moves it for every part that is added, and that is not something the design said".
- The outline is compared only when the design states it, "since the outline of a board that states none is as big as its parts need and grows with every part".
- A part whose kind changed is counted for the kind and not again for the value: "the kind wins over the value because a new kind nearly always brings a new value, and `2 values changed` would hide that the part is another one."
- Notes are counted in the sentence, last: "a note churns with every edit, which is why it is the last thing in the sentence and not red anywhere. The other choice, leaving notes to the tab, is the sentence of before."
- Only a system rail that no board lists is listed under the system: "the other choice, listing every system rail, repeats every rail change twice."
