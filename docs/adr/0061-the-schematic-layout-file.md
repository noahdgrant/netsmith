# The schematic remembers where a person moved a part, in a layout file of its own

Meets tests 1 (a file that editors write and people commit) and 3 (positions in the `.nsm` or in an existing file are the obvious homes). The status line said "proposed (the owner decided on 2026-11-06 that the schematic keeps where a person moved a part, and left the choices of the file to the author; every choice below is for the owner to review ...)". The owner accepted the choices as built on 2026-11-11. The text before the cut is `git show 31d3394:docs/adr/0061-the-schematic-layout-file.md`. The file's format and rules are the header of `crates/netsmith-view/src/hints.rs` and `GLOSSARY.md` (_Schematic layout file_); how the engine applies it is the header of `layout/hinting.rs`; the editor's reading, problems and routes are the headers of `crates/netsmith/src/editor/hints.rs` and `crates/netsmith-editor/src/api/hints.rs`, which also say what the page does with it. It replaces the paragraph of ADR 0019 that sketched a `<stem>.layout.toml`: it keeps a sidecar, an offset and not a place, and an entry for a part that is gone reported and ignored.

**Decision.** The schematic is drawn as a pure function of the design (ADR 0019), which is right for a first drawing and wrong for one someone has worked on: a person who moves a connector to the left edge, or turns a crystal, loses the move at the next edit. A move is not circuit (no check consumes it: the test of ADR 0048) and not the board's placement, so it has a home of its own, as the PCB's solution has (ADR 0032). `<stem>.sch.toml` sits beside the top-level `.nsm` file (`src/main.nsm` has `src/main.sch.toml`), plain TOML, optional, never needed to build, written by the editor and editable by hand. It holds, for each board and each sheet (a module instance, or the board's own sheet), an offset of a part's block in millimetres on the 1.27 mm grid, optionally a turn and a mirror that replace the automatic ones, or a `pin` to a place from the sheet's reference part, and an offset of a note.

**Keyed by instance path, grouped by sheet.** A part is keyed by its path in the design, never by reference designator, which a renumber changes, and under the sheet it is drawn on, so a renamed module is one table header. An offset is what the person dragged by, from where the engine puts the block, in the frame of the sheet's reference part, so it is the same when the drawing shifts as a whole. The name is `.sch.toml` because _Layout file_ is the PCB's.

**It changes nothing but the picture.** The drawing is a function of the design and the hints, and the hints are an argument and never ambient state. Empty hints give byte for byte the drawing there is without them. The file holds no wire, label or net, and the wires are routed again after a move, so no hint can make a drawing wrong. A stale entry (a part or sheet that is gone, a block that would lie on another part) is a finding with the file's line, a note in the Problems list, and the entry is ignored; what the file says wrong (bad TOML, an off-grid value) is an error with its line. The file is written in one canonical order, so a hand edit that parses and is written back changes only formatting.

**Rejected.** Absolute page coordinates (the page's frame moves when any sheet changes size). Keying by designator. Keying by full path with no sheet table (simpler, but a module rename is one edit for each part, and the file reads less like the drawing). One file for the PCB and the schematic (ADR 0030, open question 5: a regeneration of one would touch the other, and the two frames have nothing to do with each other). Inside the source (a position is not circuit, ADR 0003), in the physical file (it holds requirements, and a move is no requirement), in `netsmith.toml`. Stale entries as errors (a rename would break the view) or dropped in silence (a person who dragged a part and finds it back could not know why). Free floating-point offsets (a hand-written 1.3 would put a pin off the grid). A `lock` flag as the PCB file has (the engine is a drawing, and `pin` says it by place). Stored wire routes (they would go stale at every edit and could join what the netlist does not). JSON or a custom syntax (TOML is what ADR 0032 uses, and its reader is a dependency already).

**The cost.** Two sidecars per source file (`.pcb.toml`, `.sch.toml`), three with the physical file (ADR 0048). A comment in a file the editor rewrites is lost, as in the PCB file. A change to the file analyses the whole project, not only the drawing, which is the delay of every drag. A rename of a part inside a module leaves entries with a finding. A sheet is a top-level module instance of the board, so if sheets ever become nested the key of a part changes with them. A part with several units moves as the box of its primary unit. The sheets' arrangement on the page is not hinted, and a drag in the overview is not offered.

**Choices and what is not built.** Accepted as built by the owner, 2026-11-11: the file's name, its keys, the grid, the frame, findings and not errors, and the Alt modifier that pins. Not built, all issue #19:
- Redrawing the boards from the last build when only a `.sch.toml` changed (the drawing needs only the design, groups, rails and marks the build holds, plus the hints; it needs `Built` to be shared and a version bump with no analysis).
- Marking in the drawing the blocks that hold the sheet's reference part (a `data-block` on each part, say): such a block moves the whole drawing and arranges nothing, and the page finds out after the write and not before it.
- The preview of a drag moves the part and not its block; showing the block needs its membership in the drawing. A drag in the overview is not offered.
- "If someone wants a unit of its own arrangement, it is a key like `u1#2`, not designed here."
- Hints on the page's arrangement of sheets, and a tool that renames entries with a part.
