# An unconstrained pick is a finding, and `required` goes

Cut from 57 KB to the decision. The text before the cut is `git show 8a15457:docs/adr/0065-an-unconstrained-pick-is-a-finding.md`; source files cite its sections ("ADR 0065, 9.5"), and they are in that text. Meets the second test (a build picked two 330 ohm resistors without a word, because the obvious reading of a stated bound is that the pick honours it) and the third (`required` was rejected). The owner decided on 2026-11-06 to replace `required` by a finding about unconstrained picks and to drop `required`, and that the three bugs of section 9 are fixed, and (2026-11-07) that the pick prefers a candidate for which a waiting bound holds over the whole range. Everything else here was written by an agent, each choice with the alternatives it rejected, and is not confirmed.

`required` (ADR 0069, now superseded by this one) was meant to stop a board from leaving a value to the solver's first row. A probe showed two things. A bound on a required member satisfied `required` and then did nothing: with `.lamp.balance_resistance >= 20kohm` the build picked two 330 ohm resistors and printed only `not evaluated`. That is a bug in the solver. And `required` is the wrong tool: it is opt-in per member, so a plain `.r: Resistor` in a board is not covered; it is a test on text, so `>= 0ohm` passes it; and it fires on members that did not need to be stated. The solver knows, when it picks a part, whether anything limits the pick. When nothing does, it says so.

Three changes, in this order. First, a bound on a member that a part's field is held to by `&=` or `==` is a bound on the part's field too, since `x &= g` puts `x` inside `g`. The solver adds that bound as a relation of its own and takes it out again; it adds a refusal and never a value, so a design that meets what it states is never refused. A build that passed before can fail now, and it is exactly a build that broke a stated bound without a word (`crates/netsmith-solve/src/solve/transfer.rs`). Second, an unconstrained pick is a guideline finding: a resistor, capacitor or inductor whose value nothing limits is reported with the part, the row the solver took, and what to write. A value is limited by a domain (any range, however wide: that is how a board says "any" on purpose, `.r.resistance &= 10kohm..100kohm`), by a bound with the value alone on one side, by a check that the pick decides, or by a budget the pick changes; a ratio does not limit a size (`crates/netsmith-solve/src/solve/findings.rs`). Third, an unstated value is a finding: a value declared in a module or board that a check reads and that nothing states or works out is reported with the checks that wait for it. Both findings are a warning by default and an error under `--strict` or `guidelines = "error"`, as for open circles (ADR 0057). `required` after a type is removed from the parser, the checker, the guide and the glossary; a `pins` row keeps its own `required`, which is another word (ADR 0016).

Section 9 fixed three faults found on a real board, and two more followed. A window on a value that two equations state now reaches the pick. A load the pick does not feed no longer counts as a limit, and a ratio is not taken for a size. A group that fails is searched again with the failed one first, so that what instances are called no longer decides the board (the report of a result that depended on one name could not be reproduced; the order of the groups is what was found). A bound that waits for a later group turns a candidate away when no value can meet it, and the candidates are tried in two tiers. They are in the header of `crates/netsmith-solve/src/solve.rs`, and the user's view is `docs/LANGUAGE.md` ("A value that nobody stated", "Catalogs and how the solver picks parts").

Rejected. Keeping `required` as built: opt-in, text-based, fires where it need not. Keeping it with a stricter meaning (a value, not a bound): it would refuse `.balance_resistance >= 20kohm`, which is legitimate once the pick honours it, and leaves a plain `Resistor` uncovered. A keyword `any`: a second spelling of a range, and a language choice is the owner's. An error always: it cannot be waived without a range written only to silence it, and it would refuse boards in progress. A note: that is what failed. Reporting at the checker before the solve: whether a pick is limited depends on what propagation settles. A value that flows back from the part to the member: the first pick would force the second part to the same row, decided by which is picked first. A bound that narrows the field's domain: it changes every domain a bound reaches. Only the check afterwards: the solver would take the 330 ohm row when a 20 kohm row existed. Reporting every relation that is not evaluated: ADR 0057's reason, data missing in a part puts such notes on every board. The finding is the counterpart of atopile's check stage: atopile's `&=` intersects sets, a wide set lets the picker choose and a bound is honoured, and it has no `required`.

The cost. A module author can no longer force a board to state a value that no check reads; the remedy is to write the check, which is what the value was for. About 66 declarations in tests would warn and none needed a value line; no example and no solving block of the guide is flagged, and that is the gate. A downstream project that wrote `required` has the word to delete, and its build stops at the parser until it does. One scan of the relations for each part with a value column, and one `verify` of a few relations.

Left open, with the agent's recommendation for each, none confirmed. 1. Severity: warning by default and error under strict. 2. Which catalogs have value columns: the three E-series generics now, others when needed (one table). 3. Whether a bound on a rating counts: no, it limits the row and not the value. 4. A trivial bound or a range of the whole domain: it counts, since the finding cannot judge width and the range is the documented way to say "any". 5. Whether the unstated-value finding should exist, or the notes stay as they are: it exists, because seven of the eighteen marks in one downstream project are voltages that only a check reads. 6. "Transfer of bounds through `~` joins and `==` between two bare fields as a join. Not now. A separate decision about `==`." The transfer through arithmetic is open too. 7. A parse error that points at the removed word: no. 8. Whether a module checked alone reports an unstated member: no, both findings are made on a solved board, where the use is known.

Also open: a bound on a column other than the three E-series generics' value columns; an equation on a value that two equations state, when no pick changes any of them, which keeps the old rule; and a retry that tries only the order "failed group first", not every order or a joint search.
