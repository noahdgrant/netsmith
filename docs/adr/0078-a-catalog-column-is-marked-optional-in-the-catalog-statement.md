# A catalog column is marked optional in the catalog statement

The owner chose a marker in the `catalog` statement; its exact place, what it refuses and the fate of the standard kinds' rule were settled by an agent, each with the alternatives it rejected. Accepted as built by the owner, 2026-11-11. The text before the cut is `git show 8a15457:docs/adr/0078-a-catalog-column-is-marked-optional-in-the-catalog-statement.md`. Meets the first test (the word is syntax in the parts that projects write) and the third (a Rust list was the alternative). The user's view is `docs/LANGUAGE.md` ("An optional column"); the compatibility rule is the doc comment of `is_optional` in `crates/netsmith-solve/src/table.rs`.

ADR 0073 gave `Tvs` an optional `.breakdown_voltage` and needed a Rust list for it, `OPTIONAL_OF_KINDS` in `table.rs`. Whether a column may be empty was a fact about a catalog name, held in Rust: the four generics with synthesized parts (`Standard`, ADR 0055) and that one entry. A project's own part could not declare an optional column of its own catalog at all, so a real board that needed one had to give every row a value. ADR 0073 named the placement as the owner's to change, and issue #178 asked for the marker in the language.

A column of a `catalog` statement may end with the word `optional`: `catalog tvs { .standoff_voltage, .clamping_voltage, .peak_pulse_current, .package, .breakdown_voltage optional }`. It has the meaning ADR 0055, ADR 0058 and ADR 0073 gave the columns they called optional, and nothing new. A file of the catalog may leave the column out of its first line, and a row may leave its cell empty. A row with an empty cell is offered to a design that says nothing about the field. A design says something by narrowing it, by a relation that names it, by a `~` that joins it or by a balance of currents that sums it (`asked`, in `solve.rs`), and is then offered only the rows that record a value. A relation of the part's own definition does not count as the design asking about a column (`asked_by_design`, ADR 0092): `.gate_source_voltage >= .on_resistance_vgs` of `NMosfet` is the part's check of a value its row may record, so a row that records none is offered and the relation is not evaluated for it. A relation of the part that names an `optional` member counts (ADR 0074), and so does a statement in the design (`.q.on_resistance_vgs <= 3V`). Any column that is not marked is as it was: an empty cell takes the row out of every design, and the file must have the column. `OPTIONAL_OF_KINDS` is gone. The checker records the marked columns in the model's `Catalog` (`optional`, a subset of `fields`), so the solver's rule is the part's own and does not depend on the catalog's name.

The spelling is the one the language already has. A member says `.max_inductor_dcr: Resistance optional` (ADR 0074), and a `pins` row and a line of `lines` end with `optional` (ADR 0016). In each the word comes last on the line of the thing it qualifies and means "may be absent". The parser reads it as a plain word: `.optional` is still a column's name, because a column starts with its leading dot. A column cannot be marked twice, and nothing follows the word but `,` or `}`.

The checker refuses a column marked `optional` that the part does not have (the message of any unknown column), and the key of a keyed catalog (`catalog mcu by .mpn { .mpn optional }`), because the key names the one row a design chooses and a row without it could not be named. The columns that were optional before the marker, `temperature_coefficient` of `resistor`, `dielectric` of `capacitor` and `rms_current` of `inductor`, are marked in `std/parts/passive.nsm`. The rule that `Standard` keeps (a synthesized part leaves exactly those columns empty) stays in Rust, because synthesis is a different job, and a test of `standard.rs` requires the two to be equal, so the marker and the rule cannot drift. `is_optional` still answers yes for those three columns under the standard catalog's name, even when a part lists them without the marker, for compatibility: a project's part with `catalog resistor { .resistance, .max_power, .package, .temperature_coefficient }` built before this ADR and still does.

Rejected. A separate line, `optional .breakdown_voltage` (the form the issue gave): a second place to list columns, so a column could be listed in the statement and marked elsewhere, and it reads as a new statement and not a modifier. A leading word inside the braces: `pins` rows and members put the word last, and a word before a path would be the first place in the language where it came first. A flag on the catalog, `catalog tvs optional { ... }`, or a list after the columns: both separate the word from the column it qualifies. Marking the member instead (`.breakdown_voltage: Voltage optional`, ADR 0074): the meanings differ, since a member marked `optional` skips the relations that read it when nothing states it, and a column marked `optional` lets a row be empty. A part may want one without the other, and one word on two things would let a reader take one for the other. Deriving it from the rows, a column being optional when some row leaves it empty: the file is data and the part is the contract, the same file would read differently as rows are added, and a typo that blanks a rating would silently make the row unfit instead of an error. Removing the name-based rule of `Standard` at once: it breaks the files that listed those columns without the marker.

The cost. The marker is per part. Two parts that share a catalog name (a project's `Resistor` and the standard one) each say which columns are optional, and a file is read once for each part's statement, so the same file could be read with different columns allowed. A part whose statement does not mark a column that the file leaves out gets the error "there is no `x` column, which `catalog y` lists". The cell of an optional column that a row leaves empty means "no value"; how a design treats a part with no value stays the design's (a bound refuses the row). Nothing about price, stock or the fixed columns changes.

The three passive columns stay in Rust (`Standard`), and so does the name-based answer of `is_optional`; removing it, with a deprecation, if the marker is to be the only way, is not planned until a project needs that. The place of the word (after the column, as in a `pins` row and a member, and not a line of its own), the two refusals and the fate of the standard kinds' rule were the agent's.
