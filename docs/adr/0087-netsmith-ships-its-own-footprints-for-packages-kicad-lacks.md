# netsmith ships its own footprints for the packages KiCad lacks

Builds on ADR 0041 (netsmith makes the footprints it can and KiCad's file formats stay the format) and ADR 0043 (the generators), and adds the case neither covers: a package that is one maker's drawing, in no KiCad library and no rule a generator can state. The text before the cut is `git show 9f5a5b9:docs/adr/0087-netsmith-ships-its-own-footprints-for-packages-kicad-lacks.md`. Hard to reverse: std, the export and users' library tables depend on the name `netsmith`.

The LT8641 (`std::parts::regulator::Lt8641`) comes in one package, the 18-lead 3 x 4 mm QFN the datasheet calls UDC20(18). KiCad has no footprint for it (its `UDC-QFN-20-4EP_3x4mm_P0.5mm_EP0.41x0.25mm` is the LT3033's, a different exposed pad variation) and no symbol, so `std/kicad.toml` had no row and a board with the part could not be built until its project mapped it. The owner decided on 2026-11-08 that `std` should have a netsmith-owned footprint library. This is that library.

It is a folder of KiCad files, `std/libs/`: footprints as `.kicad_mod` in `netsmith.pretty/`, symbols in `netsmith.kicad_sym`. They are compiled into the binary (`crates/netsmith-kicad/src/stdlib.rs`) and answer to one library name, `netsmith`. A row of `std/kicad.toml` names one like any other id (`footprint = "netsmith:UDC-QFN-18-2EP_3x4mm_P0.5mm_ExpPadAA"`), so there is no new key and no new syntax. `netsmith:` ids are answered from the binary before anything else is read, so the pads are the same on every machine with no KiCad installed, and no project can list a library called `netsmith` (`Mapping::parse` and `FootprintLibrary` refuse it, as ADR 0021 and 0043 refuse the names of installed and generated libraries). A project that wants another land pattern writes its own package name in its own row.

The export copies the library into the board's output like any other: for a board with a part that uses a `netsmith:` footprint or symbol, `Libraries::write_tables` writes the library beside the `.kicad_pro` and lists it first in `fp-lib-table` and `sym-lib-table`, so KiCad's "update footprints from library" finds it. A board that uses none gets no `netsmith` files. A footprint is added only from a package drawing that was read, with the page; a package with a dimension that cannot be read is not added. The record of what was read, derived and assumed for the first footprint is `std/libs/README.md`. Tests (`crates/netsmith/tests/kicad_rows.rs` and `lt8641.rs`, `crates/netsmith-kicad/src/stdlib.rs`, `crates/netsmith-pcb/src/footprint.rs`) check every shipped footprint against its part's pin table and against the datasheet's numbers, and fail for a file that no row names.

Rejected: leaving the symbol to each project (the part stays unbuildable, the case this ADR is for) or making `symbol` optional with a generated box (a change to the mapping's meaning and a drawing in the exporters); a generator row in `crates/netsmith-pcb/src/generate/` (ADR 0043's way: one drawing's land pattern is not a rule, and the dimensions would still be code); a file fetched from a pinned URL (ADR 0041, option B: needs a network and a host); a second spelling for the same thing (`[[std_footprint]]`, `footprint_file = "..."`); letting a project's library of that name override it; always writing the library, or never writing it (a footprint embedded in the `.kicad_pcb` with no library to update from).

Cost: a wrong pad is a wrong board, and KiCad has no footprint to compare with, so the check is the datasheet itself. Before a board is ordered, compare the footprint with the maker's drawing once more, and read the `fab-notes.txt` line about the pick-and-place rotation, which is unverified until a board with the part has been assembled. The licence is not an issue as it was for KiCad's files: pad numbers and sizes are facts from a drawing, and the files are written by netsmith.

Left open: the catalog row of the LT8641 (issue #179) waits for a stock above zero. No other row maps to the footprint yet. Whether packages common across makers but not a rule (the other UDC pad variations of the family) belong here one by one, or ADR 0043's QFN rows should grow to take drawings with two exposed pads; the first is what this ADR does. The owner has not confirmed the choices taken: symbols as well as footprints, plain files and not a generator, the name `netsmith` and the `netsmith:Name` form, the precedence of the binary, and what the export writes.
