# A part's height can come from the catalog row it was picked as

Refs issues #27 and #66. Amends ADR 0045 section 11, which left "a catalog column `height`" for later. The text before the cut is `git show 0ff6fac:docs/adr/0094-a-parts-height-can-come-from-the-catalog-row-it-was-picked-as.md`. Meets the first and third tests: the cell is part of the catalog file format that projects write, and it rejects the obvious reading of ADR 0078 (an optional column).

A real 12 V automotive board has a 4 mm height limit for its 35 x 60 mm case. netsmith checks it with a `Keepout` that states `.max_height` and the `.height` of each part (ADR 0045 section 11). A part's `.height` had to be written by hand from a datasheet, and a part with none is reported `unchecked`, so every part of a real board was a warning. The numbers are in the documents that the catalog rows already cite for their ratings, and the owner's rule is that a height is read from data and never invented.

A catalog row may have a `height` cell: how tall the part's body stands above the face of the board, one length (`2.62mm`). The part's `.height` is that number when the design states none. `height` is a fixed column, like `assembly` (ADR 0024, 0084): a column of the row, not of the part. A file may leave it out and a row may leave the cell empty, which means the height is unknown, as before. No `catalog` statement of `std/` changes, so no design that built stops building, and no row is ever chosen or refused because of its height. The order, strongest first: the physical file or the source states `.height` (ADR 0045 section 11), else the picked row's `height`, else the part has no height. A stated `.height` is never compared with the row's, so a design that knows better than a document is not argued with.

The number is the greatest the document allows (the datasheet's maximum, or the nominal plus the tolerance the drawing prints, the larger when inches and millimetres disagree by rounding), never a typical value, because a height is used as an upper bound against a limit. A pin header's is the whole height with the long pin up. The cell is read once and is one length: a range, a tolerance, a negative number or another quantity is an error naming the file, line and cell. A part whose own `catalog` statement lists `.height` reads it as before. A row with a `height` has a `height:` entry in its `source` (document, revision, page, table or drawing); a cell that cannot be read from a document stays empty, and no row holds an estimate or a figure from a package's name. `fab` writes to `fab-notes.txt`, for a board that has a height limit only, how many parts have a known height and one line for each part whose height is a row's.

Rejected: an ordinary `.height optional` column of every `catalog` statement (ADR 0078). The value would then be a field the solver holds rows to, so `.c1.height &= 3mm` would pick a row and an empty cell would take a row out of every design that states a height, and "a project's statement wins" would become "a project's statement picks the row". A height from the footprint: a KiCad footprint file has no height (its `(attr ...)` is `smd` or `through_hole`, its `(model ...)` points at a 3D file and its courtyard is in plan), so it needs a STEP or VRML reader for the model's bounding box, which ADR 0045 section 5 advises against, and a model may be a drawing and not the datasheet. A height from the package's name: a package standard bounds a body and a part in it is often lower, so a table would put a number where no document of the part said it. A height from a DXF (ADR 0045 section 9). A warning when a stated height is lower than the row's, which would also fire where the design knows a lower variant is fitted. A catalog height in the editor's hover: cheap in the language, not in the built bundle.

Cost: one more name among the row's own columns, and a design cannot ask the solver for a part of at most 3 mm. A generic part (ADR 0047) has the height of the row `fab` resolves it to, which can depend on the stock a supply provider reports; a bank (ADR 0052) gives each part the row's height. No standard row had a height when this was written, so no existing board changed; rows with a height are added in their own change, with their sources (`data/jlcpcb/README.md`).

Accepted as built by the owner, 2026-11-11: the fixed column, the greatest figure as the number, the order of the sources, and `fab-notes.txt` only for a board with a limit. Not built: a 3D bounding-box reader for parts in no catalog (it would need its own marker in every report) and package-standard heights as a limit and not a height (issue #27); the editor's hover saying where a height came from (issue #19); telling the design that its stated height is lower than the row's: not planned until a board needs it.
