# A rail is on GND unless a statement says otherwise

The owner decided on 2026-11-13 (issue #624, epic #638) that std gives `Rail` the default `.neg.net ?= "GND"`: a board states ground once, by not stating it, and an isolated or analog ground overrides it on that rail (`.analog: Rail { .neg.net &= "AGND" }`). There is no new board member. This ADR records how that squares with ADR 0005 and ADR 0051. It meets two tests of the README: a newcomer would not expect a net name outside a board, and it rejects an obvious alternative.

**The default and ADR 0005.** ADR 0005 refuses `.net &=` outside a board because a net name is board-wide: a module that named a net would join every instance of itself. A rail is the one thing whose instances are meant to share a name, which ADR 0005 itself says. So the check now allows a `?=` of a `net` in an `interface`, and nowhere but a board and an interface (a module, a part, a generic and a system still get the error, now worded "names a net by default"). The default is an offer, and it takes effect only where the rail is on a board, so it names nothing in a module checked on its own. Net names are scoped by board, so two boards of a system each have their own `GND`. Decided by the owner (2026-11-13): the exception is for every interface, not for `Rail` by name, because a rule that names one std definition would let std do what users cannot.

**A default gives way to a join.** ADR 0051 counts only statements on the same field, and a value that arrives through `~` leaves the default standing. That is wrong for a net, where `~` makes one net with one name: a module's rail joined to a board rail that states `AGND` would carry a `GND` default and be reported as naming its net differently. So the default of a `net` is dropped when any pin joined to it has its net named by a `&=`. A `?=` never makes a name clash, and a statement is the only thing that can. Two rails joined with `~` that state different grounds are the same error as before.

**Where it applies.** Decided by the owner (2026-11-13): the default names a net only when a pin of a part is on the ground and a second pin is joined to it. Without the limit a rail's ground nothing is attached to would be a net of its own pin, with three effects: a bus port's reference rail (every `Logic`, `Spi` or `I2c` port has one) would be on `GND` on every board, so a mate would count each such port as carried and refuse the explicit port join of ports no connector carries (ADR 0040); a part's bus interface that has no pad for its reference would ask for one; and every unconnected `Rail` would list a ground net. With the limit, a rail used only through `pos` has no ground net, as before; `examples/power_manifold_charger` keeps five `.x.neg ~ .v5.neg` joins for that reason.

**Rejected.** A board member (`.ground &= "GND"`, joined to every rail's `neg` unless a rail says otherwise) adds a second place that names the net and needs a way for a rail to opt out that the checker can see. A rule that a rail with no ground statement is unnamed and reported would keep the 50 lines. Applying the default to every `neg` pin, whatever it is joined to, was tried and breaks the mate rule above.

**Cost.** A board that wants two defaults cannot offer a ground with `?=` (the rail has one: two defaults is an error by ADR 0051); it states it with `&=`. A board that names no ground now has one called `GND`, where an unnamed board had a net called `net-` and a terminal path (`examples/status_indicator` is one: its ground net is renamed, with the same pins). A rail whose only ground is a pin that no statement names takes the name `GND`, so an isolated converter's secondary side must state its ground, or two grounds are joined by name.

**Left open.** Whether other interfaces than `Rail` should offer net names (a bus's `vbus` rail is a `Rail` already, and no other has been asked for). Whether the reference rail of a bus port should not have a ground default at all, rather than none until a part joins it. The editor's syntax highlighter needs nothing: `?=` is read as before.
