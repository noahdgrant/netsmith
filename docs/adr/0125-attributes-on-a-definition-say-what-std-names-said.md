# Attributes on a definition say what Rust lists of std names said

Issue #631, epic #638. Owner decisions of 2026-11-13: what only the standard library could do becomes declarative attributes that std then uses itself, `#[bank]`, `#[series(E24, E96)]` and `#[role(bias)]` on a member; then, after review of the built change, the three attributes for the tools below (with `#[kind]` in place of the proposed `#[class]`), the strictness, the design file's line and what a series makes for a project's own catalog. Meets the first test (std, the design file and users' parts change) and the third (it replaces ADR 0105's convention of a name).

**What the attributes are.** `#[name]` or `#[name(arg, ...)]`, each on its own line, after the `///` lines and before a `generic` or `part`, or before a member declaration of one. An argument is a name or a text. The parser takes any name (`crates/netsmith-lang`); the checker knows the list (`crates/netsmith-check/src/attrs.rs`) and refuses an unknown or misplaced one once per definition, with "did you mean". A part has the attributes of its own definition and of the generics it provides, the definition's own first.

- `#[bank]`: a part of it stands for a number of identical parts in parallel (ADR 0052, ADR 0123), its `#[role(count)]` member. `#[bank(Capacitor)]` names the kind each part of the bank is in the design, which `CapacitorBank` states and which the `BANKS` list of #691 held; without it each part is of the bank's own kind (decided by the orchestrating agent while the owner was away, 2026-11-13: the argument was added when this change was rebased on #691). `Model::bank` is the one place that answers. A user's generic or part may be one, which ADR 0052 refused.
- `#[series(E12, E24, E96)]`: the E-series the solver may make the values of its catalog from (ADR 0047). The project's `series` key picks one: itself if offered, else the finest offered series coarser than it (`Series::within`), so `Capacitor` and `Inductor` offer E12 and E24 and an E96 project gives them E24, which `Series::for_reactive` did in Rust. A part whose definition offers no series gets no made values.
- `#[role(r)]` on a member: what ADR 0105's eight names did (`bias`, `bridge_voltage`, `current`, `supply_peak`, `supply_reverse_peak`, `limit_current`, `supply_fault_current`, `count`). The checker finds the member by the role (`Model::member_with_role`), whatever it is called. A member named `bias` with no role is a plain member. ADR 0105 is superseded.

**Three attributes for the tools.** The exporters, the placer and the router read the names of std definitions to treat a kind of part in its own way. Each now reads a declaration instead:

- `#[kind(k)]`, one of `resistor`, `capacitor`, `inductor`, `ferrite_bead`, `fuse`, `led`, `diode`, `transistor`, `crystal`, `ic`, `connector`, `mounting_hole`, `plated_hole`, `fiducial`, `label` (`netsmith_core::PartKind`). It replaces the 3D view's table of names, `is_capacitor_kind` (a decoupling capacitor), `is_series_kind` (drawn in series), the router's crystal, `CONNECTOR_GENERIC`, `is_mechanical`, the holes of a case check, the physical file's mounting hole, fiducial and label, and the `unused` rule's series passives (ADR 0083: `resistor`, `fuse`, `ferrite_bead`). One word from a closed list, not an attribute for each behaviour: a tool decides what a kind means to it, and a new behaviour needs no new syntax. Not `#[class]`, which is already a class of pin functions (ADR 0071).
- `#[value("LED")]`: what a schematic shows when the solver chose no row (`Led`, and `Header1x2`'s `Conn_01x02`), which `default_value` matched by name.
- `#[assembly(hand)]`: who assembles a part when the design, its row and the project are silent (ADR 0024). The headers and sockets state it; `hand_soldered` matched `Header*` and `Socket*`. `.assembly ?=` was rejected: it would win over the project's default and mark the choice as stated.

**The design file carries the declared kind.** `Part.declared_kind` and `Placed.declared_kind` are new fields (`"declared_kind": "capacitor"`), because the placer and the router start from the design file. The field is not `kind`, which already is the name of the part's definition (`"kind": "Capacitor"`). Every example's design file gains one line for each part that has one, and nothing else moves; the pick locks are unchanged.

**What a series makes for a project's own catalog.** A catalog with an entry in `crates/netsmith-solve/src/standard.rs` (`resistor`, `capacitor`, `inductor`, `led`) makes its parts as before: packages, tolerance classes, a package's power rating and a capacitance with no curve are facts of the catalog that the language cannot state, and any part that lists the catalog gets them. Any other catalog with a `#[series]` gets each value of the series from 1 p to 9.1 G in its first column, at the series' own tolerance (E12 10%, E24 5%, E96 1%, IEC 60063), with every other column what the design states (`Spec::Series`); with no file it is those values alone. A member marked `#[role(value)]` was not taken, because the first column of a `catalog` statement already is the value in std.

**What stays a name, and why.** `dc resistor | diode | nmos | pmos | linear_regulator | switching_regulator | source` (ADR 0076) is not a list of std kinds: each is a model of the DC analysis, built into the solver, that a user's part already states the same way std does. The interfaces read by name (`Rail`, `Logic`, `Levels`, `I2c`, `Place`, `Outline`, `Cutout`, `Keepout`, `CaseModel`, `Mating`) and their members (`pos`, `current`, `peak`) are the language's own vocabulary of ports, not kinds of part; this record does not cover them. The four standard catalogs' names in `standard.rs` are catalogs, which ADR 0052 already kept apart from kinds. KiCad's mapping (`std/kicad.toml`) keys kinds by name as data a project can extend.

**Rejected.** Deriving a bank from a numeric `.count` (a user part with a count is not always a bank), a keyword before the definition (`bank generic`), and keeping the names with an attribute beside them (two ways to say one thing).

**Cost.** The rules are strict: a project part that relied on a name (`.current` of a switch with a `bridge`) needs the role, and the examples' four switches gained `#[role(current)]`; a part that lists a standard catalog gets made values only with a `#[series]`. A `Capacitor` is no bank; the standard `CapacitorBank` carries `#[bank(Capacitor)]`, `#[role(count)]` on its `.count` and `Capacitor`'s `#[series(E12, E24)]`.

**Left open.** A warning for a member named like a role with no role; members of an interface by role; a role written twice in one part (the first is read).
