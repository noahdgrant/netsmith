# A sheet dragged in the overview keeps its place in the schematic layout file

Meets tests 1 (a key of a file people commit) and 3 (it rejects the obvious offset from where the arrangement puts a sheet). ADR 0061 left the sheets' arrangement on the page unhinted and a drag in the overview not offered; the owner decided in issue 999 that dragging a sheet in the overview writes its position to `<stem>.sch.toml`, the file and mechanism parts already use, and that sheets never moved stay arranged by their connections. The choices below are the author's. The rules are the headers of `crates/netsmith-view/src/hints.rs` and `sheets.rs` (`placed_frames`, `arrange`); the page's are the header of `crates/netsmith-editor/src/api/hints.rs`.

**Decision.** A sheet's table holds `at = [x, y]`: the top-left corner of the sheet's box, title included, in millimetres on the 1.27 mm grid, from the page's origin. The origin is the corner the first box of the automatic arrangement has, so it does not move when a sheet changes size. The board's own sheet has its `at` in the board's table (`[Trellis]`), a module instance's in its sheet's table (`[Trellis.sheets.stage]`), written before the sheet's parts. The drawing puts each placed box there, to the nearest grid step, and moves its whole drawing with it. The other boxes are set out as before, in the order of their connections and in rows, and a box that would come within the gap between sheets of a placed one goes on past it, in its row or the next. With no `at` the drawing is byte for byte the one before.

**What a drop writes.** The overview is a grid of cards in the order the drawing sets the sheets out, so a card is dropped on another card and not on a point of the page. The dragged sheet's `at` becomes the corner that card's sheet has in the drawing: the dragged card takes its place, and the sheets never moved are set out again round it. When the sheet dropped on has a place of its own the two swap, so a drop never asks for one box on another. Nothing else is written: a drag of a sheet never moved does not fix its neighbours. `Delete` on a placed card, and "Clear the layout of this module", take `at` out.

**Findings, not errors.** As for a part (ADR 0061), what the file says wrong is an error and what no longer fits the drawing is a finding at the line of `at`, and the sheet is arranged as if it had none. These are findings: a sheet drawn as several numbered boxes (it has no one place), a board drawn as one sheet, a box that would lie on a box placed before it in the file, and a board whose parts are all in modules (it has no sheet of its own).

**Rejected.** An offset from where the arrangement puts the sheet (`dx`, `dy`, as a part has): the arrangement changes whenever any sheet grows, so the same offset would put the sheet somewhere else after every edit. A place from a sheet's reference part (a part's `pin`): a sheet has no parent sheet to be measured from. A slot number in the card grid: it says nothing to the drawing, the KiCad export or a reader of the file, and the grid's columns change with the window. Pinning every sheet on the first drag, so the arrangement no longer moves anything: the owner asked that sheets never moved stay arranged by their connections. The same key name as a part's `pin`: the two frames differ, and a reader would take one for the other. A drop between two cards: the grid has no gap a person can aim at.

**The cost.** A placed sheet stays where it is when its neighbours grow, so a big change leaves a gap or pushes the others round it. The swap writes a second sheet that the person did not drag. A sheet cut into boxes cannot be placed. A drop looks only at the corner of the card it lands on, not at its size, so a large sheet dropped on a small one pushes more of the rest. Comments in the file are still not kept when the editor writes it (ADR 0061).

**Left open.** A 2-D placement that also uses the row above to put a box under its most-connected neighbour: issue 999 left it optional, and it would show only in the whole drawing (the KiCad export), not in the card grid, so it is not built. Placing the boxes of a cut sheet one by one.
