# The schematic of record is the editor's drawing, written by netsmith's own PDF writer

Meets tests 1 (a file of the fab package that people hand on) and 3 (it rejects printing the KiCad schematic and an SVG converter from a library). The owner decided in issue 1091 that the picture of record is the editor's schematic, written as a PDF with no KiCad and no browser, by `netsmith view schematic --format pdf|svg|png` and in the fab package as `<board>-schematic.pdf`. The choices below are the author's. The rules are the headers of `crates/netsmith-draw/src/lib.rs` (the interface), its `svg.rs`, `pdf.rs` and `raster.rs`, and `crates/netsmith-view/src/export.rs` (the sheets and the title block).

**Decision.** Every output is a function of the SVG the editor shows (`render_layout`), and of nothing else: `netsmith-draw` reads that SVG into a flat picture of paths and text (the subset of SVG and CSS netsmith writes, with its `<style>` resolved and what draws nothing left out), and writes the picture as a PDF or fills it into pixels. The command line, `board fab` and the editor's export all draw the SVG with the same inputs (`netsmith_fabricate::schematic`) and hand it to the same writer, so they give the same bytes. A sheet is what the SVG marks as one (`g.module-sheet` with its `data-bounds`), and a PDF page is a sheet, sized to it, with a margin and a title block under it. The PDF is 1.4, vector, its text in Helvetica and Courier (and Symbol for Greek letters) with the Windows Latin encoding, so no font is embedded and its text can be searched; its streams are compressed with netsmith's own deflate; it has no date and no identifier. The PNG is anti-aliased and its text is the stroke font of the silkscreen, so no font file is read.

**Why from the SVG.** The editor already draws the schematic as SVG with styles a person arranged and checked; a second drawing code for paper would drift from it. Reading the SVG back costs a reader of a small subset, and keeps one drawing. The same reader serves the other pictures netsmith draws as SVG (the board's copper, `view pcb`, issue 1086; the Gerbers, `view gerber`, issue 1105).

**Rejected.** The KiCad schematic printed by `kicad-cli sch export pdf`: it needs KiCad (ADR 0097) and is KiCad's drawing, not the one the editor shows. A library that converts SVG to PDF or PNG (`svg2pdf`, `resvg`): they bring a font database and a text shaper, and their output moves with their releases, so the bytes of a fab package would change with a dependency. Printing the page from a headless browser: it needs one. Embedding a font: the standard fonts are in every PDF reader, and an embedded font is a licence to track and a megabyte per file. One page for the whole board: a board drawn by module is a page of boxes that no printer can read.

**The cost.** The reader knows only what netsmith writes: a drawing that uses another SVG feature (a gradient, a clip path, a `<use>`) loses it until the reader learns it, and a selector with a pseudo-class is left out on purpose. The PDF's letters are Helvetica, not the editor's sans-serif, so a long name may sit a little wider or narrower than on screen; the PNG's are the stroke font, wider still. Text in a script the standard fonts lack is written `?`. A `vector-effect: non-scaling-stroke` line is taken as CSS pixels on a millimetre page.

**Left open.** A board revision in the title block (the project has no such field; the release of netsmith that drew it is there). A PDF outline (bookmarks) of the sheets. Links between the stubs of a net on different pages.
