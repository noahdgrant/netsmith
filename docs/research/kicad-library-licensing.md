# KiCad libraries: inventory, licence reading and the `.kicad_sch` reader

A working document. It holds what ADR 0041 measured and read on 2026-11-02, moved out of the ADR so that the ADR is one page (`git show 0eaf326:docs/adr/0041-self-contained-libraries.md` has the full text with its staged plan). ADR 0097 (no KiCad install) cites the licence reading below. Nothing here is legal advice, and no choice here is made: the open questions are in ADR 0041.

## Inventory (measured 2026-11-02)

Measured against the installed KiCad 9.0 libraries (symbols 233 MB in 225 files, footprints 213 MB in 146 `.pretty` folders, 3D models 4.8 GB) and the upstream tag `9.0.9.1`, whose `tar.gz` archives are 10.8 MB (symbols) and 12.0 MB (footprints).

- `std/kicad.toml` then used 67 rows: 32 distinct symbols from 7 libraries (18.8 MB; 109 kB of text is used, a parent included when a symbol `extends` one) and 50 distinct footprints from 17 `.pretty` folders (25.1 MB; 213 kB in 50 files, the largest 20 kB). The two pin-header libraries alone are 15.9 MB, because they hold every size.
- Two more things are used: `power:PWR_FLAG` (the power-flag rule) and the 3D model path inside each footprint (`${KICAD9_3DMODEL_DIR}/...`), which the exported `.kicad_pcb` keeps verbatim. netsmith never opens a 3D model, so the 4.8 GB need not be fetched.
- Building the six examples then wrote 8 distinct symbols and 9 distinct footprints.
- A typical four-layer product needs more than the standard rows. This is an estimate, from KiCad's 48 demo schematics (14 projects, older and simpler than a modern product): 0 to 26 distinct stock footprints per project, median about 12, a long tail of chip passives, SOT, SOIC, TSSOP, QFN/DFN, LQFP and a connector or two. 336 of the demos' 382 distinct symbols are project-local, which is itself the finding: a real design's ICs are mostly not in the stock libraries under the name or pinout the design wants. Expected gap: 25 to 60 distinct footprints and 15 to 40 distinct symbols per product, of which 5 to 15 are ICs that come from a manufacturer's or LCSC/EasyEDA's download or are drawn by hand. The whole stock set is 22.8 MB as `tar.gz`, about 446 MB unpacked.
- Parse cost is not a problem: `netsmith build examples/four_layer.nsm` read about 12 MB of symbol libraries over the slow `/mnt/c` mount in 0.37 s in a release build.

## Licensing (sources read, and what is not known)

Sources: `https://www.kicad.org/libraries/license/`, the `LICENSE.md` of the `kicad-symbols` and `kicad-footprints` repositories on GitLab (the GitHub copies are archived and cover KiCad 5), the README of `kicad-footprint-generator`, and the `LICENSE.md` the KiCad demo projects carry.

The libraries are CC BY-SA 4.0 with one exception, in the KiCad project's words: "To the extent that the creation of electronic designs that use 'Licensed Material' can be considered to be 'Adapted Material', then the copyright holder waives article 3 of the license with respect to these designs and any generated files which use data provided as part of the 'Licensed Material'." The explanation under it says that using library data in a project does not by itself require the design or its generated files to be CC BY-SA, and then: "if you wish to redistribute the KiCad libraries, or parts thereof (including in modified form) as a collection then the exception above does not apply. Redistributed library collections must be shared under the same license agreement. Under these circumstances, the libraries must also retain attribution information, including the license documents which are distributed with the library files."

What follows, as a reading and not as advice:

- Using the libraries, which is what a design and the files netsmith writes do, is covered by the exception: the exported `.kicad_sch` holds copies of symbols in its `lib_symbols` and the `.kicad_pcb` copies of footprints. Those are "generated files which use data provided as part of the Licensed Material", so a netsmith user's output carries no CC BY-SA obligation. This holds equally if the libraries were fetched or bundled.
- Redistributing library files, or parts of them, is outside the exception. The page says "parts thereof" and "including in modified form", so a subset of 32 symbols and 50 footprints, and a symbol flattened from its `extends` parent, are parts and a modification. For such a redistribution the CC BY-SA 4.0 conditions apply to the redistributed files: attribution, an indication that they were modified, and ShareAlike (CC BY-SA 4.0 or a licence CC lists as compatible; MIT is not on that list).
- Does embedding in a binary count as redistribution? Compiling a file into an executable (`include_str!`) copies it into what netsmith ships. The page does not say that a collection must be a separate file set, and it does not say that embedding in a program is excepted. Not known. The cautious reading is that it is a redistribution of the files.
- Does it infect netsmith's own licence? ShareAlike applies to "Adapted Material", a work based on the licensed material. Source code that reads library files at run time is not based on them, and data files in their own directory with their own licence file are an aggregate of separately licensed works. Whether a binary that embeds the files is one work or two is the open question of the previous bullet; Creative Commons' guidance on collections was not fetched. A generator that copies a library's geometry would be an adaptation in any case. Not known, and not for the implementer to decide.
- The workspace says `license = "MIT"` in `Cargo.toml` but had no `LICENSE` file at the root then. An MIT crate and a CC BY-SA directory in one repository is common, but "MIT" is then true of the code only, and the README must say so.

Other facts:

- `kicad-footprint-generator` (it wrote files such as `R_0402_1005Metric`) is GPL-3.0-or-later with some MIT and LGPL files. Translating its Python into Rust would make the Rust a derivative of GPL code. A footprint generator for netsmith must work from IPC-7351 and the package drawings, not from that code. Whether the IPC-SM-782 tables can be read freely is the owner's to check (IPC standards are paid documents).
- The 3D models are a third repository (`kicad-packages3D`), whose licence was not read.
- KiCad's demo projects carry a `LICENSE.md` of their own (CC BY-NC-SA 4.0 with a commercial-use exemption, in the one that was read). They are fit as a local test corpus when read from the user's KiCad install, and must not be copied into the repository.
- The installed KiCad rewrites files (Windows line endings; `generator "pcbnew"` in place of `"kicad-footprint-generator"`). Installed `Device.kicad_sym` differs from upstream `9.0.9.1` in 644 lines after line endings are ignored. So a checksum can only pin upstream content, never an installed copy, and the symbol content really does move between 9.0 patch releases.
- A footprint's name and the pad numbers are facts about a package. Whether pad geometry computed from the IPC formulas can be freely reproduced is not settled.

## The options weighed, and one format

Four ways to get library bytes were weighed: (A) bundle a subset in the repo (about 320 kB for the standard set, in a separate directory with the licence files and a `NOTICE`; needs the owner's licence decision, and embedding in the binary is unclear above); (B) fetch on first use (a lock file with URL, tag, commit and checksums, no library bytes shipped; needs the network once per machine or project, 20 to 23 MB); (C) netsmith's own drawings (generator code and its tests, MIT; a footprint that is slightly wrong makes a bad board; the symbol drawings for R, C and LED are trivially original, a QFN is not); (D) a mix. C needs care to be worth doing: KiCad's own footprints for chip passives, SOT, SOIC, QFN and headers are themselves generated from parameters, so generated footprints named like KiCad's can be tested against the real ones (pad centre, pad size, courtyard, 0.01 mm). Without that test C should not be built.

The library format stays KiCad's `.kicad_sym` and `.kicad_mod`, with none of our own: one way to say a thing (ADR 0001); the export is in that format and embeds each symbol and footprint verbatim, so a native format would need a converter each way and a lossless round-trip test; everything arrives in it (manufacturers' downloads, `easyeda2kicad`, KiCad's editors); and size and speed do not call for one. atopile also chose "KiCad's format on disk, converted from a manufacturer-neutral source on demand" (read from its public material; the part that explains the mechanism was not reachable, so this is partly inferred), a precedent and not evidence of what is best here. The EasyEDA route has its own terms of use and is not recommended for a first version.

## The `.kicad_sch` reader (a plan, not built)

`netsmith compare` on a `.kicad_sch` still asks `kicad-cli sch export netlist`. A reader in `netsmith-netlist` (`from_kicad_schematic`, beside `parse.rs`, reusing `netsmith-fab::sexp`) would need no library, since the file embeds every symbol in `lib_symbols`. `compare` works on connectivity and ignores net names and designators (ADR 0017), so the reader has to get the groups of pins right and not the names. In the KiCad demo corpus (48 files, format versions 20230121 to 20250114): 6469 wires, 1195 junctions, 2072 local labels, 224 global labels, 252 hierarchical labels, 122 power symbols, 460 no-connect flags, 17 sheet blocks, 191 bus wires, 134 bus entries. The rules, in the order the algorithm applies them:

1. Placed symbols to pin points: the pins of unit 0 and of the placed unit and body style, transformed by rotation and mirror, y flipped, compared as integer nanometres as KiCad does.
2. Wires, junctions, pins and labels to nets per sheet, by union-find over points: a pin or label point on a wire's middle joins it; two wires crossing, or a wire end on another wire's middle, join only with a junction (to be checked against `kicad-cli`: KiCad's rule changed across versions); stacked pins at one point are one connection; a no-connect flag changes the ERC and not the netlist.
3. Names merge nets: local labels inside one sheet instance, hierarchical labels with the sheet pin of the same name in the parent, global labels across the design, a power symbol as a global label named by its `Value`, a hidden `power_in` pin as a global label named after the pin. Net-tie footprints join nets on the board, not in the schematic, and are not handled.
4. Hierarchy: the walk is by sheet instance and not by file, since one file may be instantiated more than once; a designator is the `reference` in `(instances ...)` whose path equals the instance's; files before KiCad 6 are refused with the version named.
5. Units: a multi-unit part is several placed symbols with one reference and one component; pins with the same number are one pin.
6. Buses (the largest piece, the most likely to disagree with KiCad in an edge case): `D[0..7]`, `{A B}`, aliases, bus entries, buses on hierarchical pins; members join by name.
7. From nets to the `Netlist`: pins grouped by net, power and flag symbols dropped, one-pin nets dropped.

Estimated 1200 to 1800 lines of Rust and as many of tests. Validation, all of it runnable today: a differential test against `kicad-cli sch export netlist` on the schematics netsmith generates, on the 48 demo schematics read from the installed KiCad (not copied into the repository), and on small hand-made schematics for each rule above, kept as text fixtures; the comparison is `netsmith compare --by-refdes` (any difference in the pin groups fails, a difference in net names alone does not); and a property check that the netlist read from the exported `.kicad_sch` equals that of the `.kicad_pcb` and of the design itself, which needs no KiCad and runs in CI. Risks: the junction and wire-end rules differ between KiCad versions, the bus rules are intricate, KiCad may keep or drop a component the reader keeps (`on_board no`, `exclude_from_board`), hidden power pins create nets no wire shows, and a file newer than 20250114 must be refused by version and not misread. A design that cannot be read is an error naming the file, line and version, never a guess.
